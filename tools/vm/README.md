# Автоввод и снимки экрана в тестовой VM `SG-Test`

Оснастка, чтобы проверять **интерфейс** Windows-сборки живьём, а не только код.
До неё через PowerShell Direct можно было запустить приложение и почитать журналы, но
нельзя было ни нажать кнопку, ни увидеть экран — а часть правок иначе не проверяется вовсе
(экран логов, вёрстка настроек, плашки на главном).

## Зачем это устроено именно так

PowerShell Direct попадает в **сессию 0**, где рабочего стола нет: окна не существует, курсора
нет, снимок делать нечего. Поэтому `sgui.ps1` запускается **задачей Планировщика** в
интерактивной сессии 1, а хост общается с ней через файлы.

## Разовая настройка в госте

```powershell
# приложение — в сессию 1
schtasks /create /tn sgrun /tr "%LOCALAPPDATA%\Programs\SilentGate\silentgate.exe" /sc once /st 00:00 /RU sgtest /IT /F
# оснастка — туда же
schtasks /create /tn sgui /tr "powershell.exe -NoProfile -ExecutionPolicy Bypass -File C:\sgui\sgui.ps1" /sc once /st 00:00 /RU sgtest /IT /F
```

⚠️ **`/IT` обязателен, `/RP` указывать НЕЛЬЗЯ.** Пароль вместе с `/IT` делает задачу
нерабочей, и `schtasks /Run` отвечает «Элемент не найден» — ошибка, которая ничего не
объясняет.

## Как пользоваться

Команды кладутся в `C:\sgui\sgui.cmd`, по одной на строку, затем `schtasks /run /tn sgui`.
Итог — `C:\sgui\sgui.log` (что произошло) и `C:\sgui\sgui.png` (снимок окна).

| Команда | Что делает |
|---|---|
| `shot` | снять окно приложения в `sgui.png` |
| `click <x> <y>` | щёлкнуть по координате **снимка** |
| `key <VK>` | послать код клавиши (десятичный) |
| `wait <мс>` | подождать |

Перенос снимка на хост — одним вызовом, без печати в консоль (иначе base64 забьёт вывод):

```powershell
$b64 = Invoke-Command -VMName SG-Test -Credential $cred -ScriptBlock {
  [Convert]::ToBase64String([IO.File]::ReadAllBytes('C:\sgui\sgui.png')) }
[IO.File]::WriteAllBytes($dst, [Convert]::FromBase64String($b64))
```

## ⚠️ Четыре грабли, на которых здесь уже постояли

1. **`.ps1` для гостя писать в UTF-8 С BOM.** PowerShell 5.1 без BOM читает файл как ANSI,
   кириллица превращается в мусор, и скрипт падает на разборе — с сообщением про
   «отсутствует закрывающий знак `}`», то есть указывающим не туда.
2. **Координаты клика — ОКОННЫЕ, те же, что на снимке.** Снимок делает `PrintWindow`, а он
   рисует окно целиком (с заголовком) в холст клиентского размера. Считать координаты
   клиентскими — значит промахиваться на высоту заголовка **молча**: курсор встаёт куда
   просили, окно на переднем плане, а нажатие приходится мимо цели.
3. **`SendInput`, а не `mouse_event`.** Устаревший `mouse_event` доходит как движение
   (подсветка наведения появляется), но нажатия Flutter не видит. И структура `INPUT` обязана
   быть ровно 40 байт на x64: лишние поля «для выравнивания» дают 48, а `SendInput` на
   несовпадение размера отвечает нулём и молчит.
4. **`PrintWindow` вызывать с флагом 2** (`PW_RENDERFULLCONTENT`): без него окна с аппаратной
   отрисовкой — а Flutter именно такое — выходят пустыми.

## Чего оснастка не умеет

Читать текст с картинки. Проверка вида «в журнале есть такая-то строка» делается чтением
файла через PowerShell Direct, а снимок нужен для вёрстки и состояния экрана.
