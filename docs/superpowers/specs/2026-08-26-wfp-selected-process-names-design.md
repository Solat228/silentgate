# WFP для выбранных приложений по имени файла

## Цель

Правило приложения с `byName=true` должно действовать по basename исполняемого файла,
независимо от каталога и номера версии в каталоге. Это относится к двум слоям:

- обычная маршрутизация sing-box — сохранить существующее `process_name`;
- аварийная блокировка Windows Filtering Platform (WFP) — добавить динамическое
  сопоставление имён с текущими полными путями, потому что WFP принимает только AppId,
  полученный из полного пути.

Правила с `byName=false` остаются точными правилами по полному пути. Наблюдение не должно
распространяться на невыбранные программы.

## Ограничение WFP

`FWPM_CONDITION_ALE_APP_ID` не поддерживает basename или маску пути: `FwpmGetAppIdFromFileName0`
выдаёт AppId только для существующего полного пути. Поэтому WFP-фильтр по имени напрямую
невозможен без callout-драйвера. Динамический слой решает задачу безопасно в user mode:
наблюдает запущенные процессы, берёт пути только тех процессов, чей basename есть среди
выбранных имён, и атомарно обновляет набор WFP-фильтров.

Это покрывает все экземпляры выбранного имени, уже запущенные или запущенные после включения
VPN. Фильтр применяется к сетевым соединениям процесса после его появления; уже установленные
соединения WFP не пересоздаёт.

## Поток данных

1. `WindowsEngine._writeKillSwitchPlan` разделяет выбранные правила:
   - `byName=true` → `blockedAppNames` или `allowedAppNames`;
   - `byName=false` → существующие `blockedAppPaths` или `allowedAppPaths`.
2. `KillSwitchPlanFile` сохраняет оба набора в JSON и читает их с обратной совместимостью:
   старые файлы без новых полей означают пустые списки имён.
3. `TunHelper` читает план и материализует имена через `ProcessListWindows.enumerate()`:
   - сравнение basename регистронезависимое;
   - в план попадают только пути процессов с выбранным именем;
   - имя без запущенного процесса пока не даёт WFP-фильтра, но сохраняется в файле плана.
4. В существующем общем цикле помощника выполняется периодическое обновление материалации.
   При появлении нового пути или нового экземпляра:
   - старый набор не снимается отдельно;
   - `KillSwitchHold.reengage` заменяет фильтры одной WFP-транзакцией;
   - при ошибке сохраняется предыдущий рабочий набор и причина пишется в лог.
5. Если процесс с выбранным именем запускается после подключения, следующий проход наблюдателя
   добавляет его полный путь. Если процесс завершился, старый фильтр можно оставить до конца
   сессии: он не ослабляет защиту и не влияет на другой путь.

## Безопасность и отказоустойчивость

- Сканируются только имена из `blockedAppNames` и `allowedAppNames`; глобального правила по
  basename не будет.
- Пустой список выбранных программ в режиме `onlySelected` остаётся законным пустым планом и
  не запрещает запуск ядра.
- Ошибка разрешения пути одного процесса не отменяет остальные пути и не рушит весь kill
  switch. Явные правила по полному пути сохраняются.
- Полная блокировка, серверные адреса, loopback, DHCP, собственные бинарии и правило туннельного
  интерфейса не меняются.
- При отсутствии живого процесса с выбранным именем подключение не должно падать только из-за
  отсутствия материалации: процесс ещё может быть запущен позже.
- Устаревший полный путь из старых данных по-прежнему пропускается с записью в журнал; он не
  становится разрешением для другого файла.

## Изменяемые компоненты

- `core/engine/windows/wfp_rules.dart` — поля имён и материализация в пути.
- `core/engine/windows/tun/kill_switch_plan_file.dart` — поля JSON.
- `core/engine/windows/windows_engine.dart` — разделение выбранных правил по имени/пути.
- `core/engine/windows/tun/tun_helper.dart` — разрешение имён и периодическое обновление.
- `core/engine/windows/process_list_windows.dart` — переиспользуется без отдельного API.
- тесты плана, материализации, сохранения селекторов и жизненного цикла обновления.

Обычный конфиг sing-box не переписывается: существующие `process_name` и
`process_path_regex` уже имеют нужную семантику.

## Проверка

1. `flutter analyze`.
2. Полный `flutter test`; отдельные стражи проверяют:
   - имя сохраняется отдельно от пути;
   - путь сохраняется отдельно от имени;
   - материализация включает все текущие пути выбранного имени и не включает другие имена;
   - появление нового пути приводит к обновлению держателя одной транзакцией;
   - пустой `onlySelected` не блокирует запуск.
3. Живая проверка только в выделенной Hyper-V VM `SG-Test`:
   - два экземпляра тестового `claude.exe` из разных каталогов;
   - выбранное правило по имени включает оба пути;
   - правило по пути включает только указанный путь;
   - после запуска второго экземпляра при уже поднятом туннеле он попадает в обновлённый набор;
   - при остановке ядра выбранные процессы не получают прямой выход до восстановления;
   - стенд выключить после проверки.

Проверка на хосте запрещена: WFP действует на всю машину.
