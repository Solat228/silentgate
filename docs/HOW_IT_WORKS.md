# Как это работает: язык, сборка, перехват трафика (система прокси vs TUN)

Сохранённое пояснение по принципу работы SilentGate. Дополняет [ARCHITECTURE.md](ARCHITECTURE.md).

---

## На каком языке написано

| Слой | Язык | Кто пишет |
|---|---|---|
| Интерфейс + логика (парсер, конфиг, движок, экраны) | **Dart** (Flutter) | наш код в `app/lib/` |
| Нативная обёртка окна Windows | **C++** | генерит Flutter (`app/windows/runner/`) |
| VPN-ядро `xray.exe` | **Go** | готовый бинарник (не пишем, только скачиваем) |

Серверная часть (Remnawave API, Telegram-авторизация, оплата) — **Python** (ваши существующие боты).

## Как скомпилировать в exe

> ⚠️ Путь проекта содержит `!` (`I:\!Backup\…`) — из-за этого сборка Flutter под Windows падает
> (ограничение MSBuild/CMake). Собираем с «чистого» пути через junction.

```powershell
# один раз: junction на чистый путь
cmd /c mklink /J C:\dev\silentgate "I:\!Backup\!Projects\!VPN\SilentGateApp"

# сборка/запуск (flutter уже добавлен в PATH):
cd C:\dev\silentgate\app
flutter pub get
flutter run -d windows          # запуск для разработки
flutter build windows --release # готовый exe в build\windows\x64\runner\Release\
```

Dart-задачи (`analyze`, `test`, `dart run`) работают и по «грязному» пути — junction нужен только для сборки.
Готовый release-exe самодостаточен, если рядом лежат `xray.exe` + `geoip.dat` + `geosite.dat`.

## Перехват трафика: два режима

### A. Системный прокси (текущий режим MVP)

```
Приложение → системный HTTP-прокси 127.0.0.1:10809 → xray.exe → VLESS/Reality → сервер
```

Прописываем в реестр Windows (WinINET) адрес локального порта Xray. **Без драйвера и прав администратора.**
Минус: перехватываются только программы, уважающие системный прокси; UDP и «непрокси-aware» приложения идут мимо.

### B. TUN-режим / «TUN-провайдер» (как в Happ — полный туннель)

```
ВСЕ приложения → маршруты ОС → виртуальный адаптер TUN (wintun)
   → tun2socks (hev-socks5-tunnel) → xray.exe → VLESS/Reality → сервер
```

Создаётся виртуальная сетевая карта (TUN); ОС отправляет туда весь трафик (TCP+UDP, все приложения).
`tun2socks` вынимает IP-пакеты и передаёт в Xray. Это полный VPN. Требует прав администратора.

**«TUN-провайдер»** — тот, кто выдаёт приложению TUN-устройство:
- Android — системный `VpnService`;
- iOS — `NEPacketTunnelProvider`;
- Windows/десктоп — своего системного нет, поэтому драйвер `wintun.dll` напрямую + привилегированная служба-хелпер.

**В Happ:** десктоп = GUI (Qt) → привилегированный демон `happd` → он запускает `xray` и для TUN
поднимает отдельный движок с wintun. Мобильные — TUN даёт ОС.

**У нас:** `wintun.dll` уже скачан вместе с ядром. TUN-режим запланирован (этап M5): добавить
`hev-socks5-tunnel` (MIT) + службу-хелпер по модели `happd`. Настройки TUN/Провайдер/Режим уже в UI,
сам датапуть — следующим этапом.

## Проверка подписки Remnawave

Приложение шлёт GET на sub URL с заголовками устройства; в ответе:
- тело = base64-список `vless://…`/`trojan://…` (парсит [share_link_parser.dart](../app/lib/core/parser/share_link_parser.dart));
- заголовки = мета: `Profile-Title`, `Subscription-Userinfo` (трафик/срок), `Profile-Update-Interval`, `Announce`.

Если подписка неактивна/истекла, Remnawave отдаёт вместо серверов заглушки-уведомления на `0.0.0.0:1`
(«Ваша подписка истекла», «ID для продления» и т.п.) — это норма, реальные ключи появляются после оплаты.
