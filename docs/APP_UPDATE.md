# Автообновление приложения

Как SilentGate узнаёт о новой версии себя. Не путать с обновлением **подписки** —
про него отдельный документ `SUBSCRIPTION_UPDATE.md`.

⚠️ Этот документ переписан в 1.13.0: прежняя редакция описывала один настраиваемый
эндпоинт («Эндпоинт версии» в настройках) — поле убрано ещё в 0.9.x, а документ этого
не отражал. Технический контракт серверной части — в `docs/APP_UPDATE_SERVER.md`,
здесь — как это устроено со стороны приложения.

## Источники — два, канала — тоже два

| | Источник | Роль | Отдаёт беты? |
|---|---|---|---|
| 1 | GitHub Releases, `/releases/latest` | основной, стабильный канал | нет — `/latest` исключает пре-релизы по определению GitHub |
| 2 | `silentgate.lol/api/app-version` | запасной для (1) | нет |
| 1б | GitHub Releases, `/releases` (СПИСОК) | основной, **бета-канал** | да |
| 2б | `silentgate.lol/api/app-version-beta` | запасной для (1б) | да |

Запасные источники существуют не для красоты: у части пользователей `api.github.com`
не открывается вовсе (TLS перехватывается на стороне провайдера — воспроизведено в
чистой VM без VPN при живом `github.com`). Клиентом пользуются именно там, где
интернет фильтруют, поэтому «GitHub недоступен» здесь обычное дело, а не авария.
Порядок жёсткий: спрашиваем GitHub, при ЛЮБОМ его отказе — сайт; пока GitHub отвечает,
сайт не трогаем вовсе.

## Галочка «Получать бета-версии» (`AppSettings.betaChannel`, 1.13.0)

По умолчанию **выключена**. Меняет ТОЛЬКО то, какой из четырёх источников выше
спрашивает `AppUpdate.check()` — на основной манифест автообновления
(`silentgate.lol/api/app-version`) она не влияет никак.

- **Выключена** — источники (1)/(2), ровно так же, как было всегда.
- **Включена** — источники (1б)/(2б): GitHub отдаёт СПИСОК релизов (`GET /releases`,
  без `/latest`) от новых к старым по дате публикации; первый элемент — это и есть
  «новейшее, включая пре-релизы», сравнение версий между элементами списка не
  требуется. Черновики (`draft: true`) отбрасываются на разборе — они не
  опубликованы, предлагать их как доступную версию нечестно.

⚠️ **Признака канала в ОСНОВНОМ манифесте намеренно нет.** Разговор возник из-за
1.12.0: сайт-агент выложил её как GitHub-пререлиз (`prerelease: true`,
`make_latest: false`) и в `/opt/updates/beta/`, но не тронул `/api/app-version` —
именно поэтому автообновление её никому не разослало. Если бы признак жил в
основном манифесте, включение поля на сервере само по себе разослало бы бету всем
подряд без их решения. Отдельный источник — единственный способ спросить о бете, не
трогая канал, которым пользуются все.

При найденном релизе UI показывает плашку «БЕТА» (`AppRelease.isBeta`), если ответ —
пре-релиз (`prerelease: true` у GitHub, поле `beta`/`channel` у сайта), и отдельную
строку про то, что это пре-релиз и автообновление такие версии не рассылает.

## Кнопка «Прежние версии» (1.13.0)

Список релизов (1б) уже запрашивается ради беты — тот же список годится и для отката:
`AppUpdate.fetchReleaseHistory()` отдаёт последние N релизов (версия + дата публикации
+ ссылка), диалог в настройках их показывает с кнопкой «Открыть».

⚠️ **Приложение НИЧЕГО не скачивает и не устанавливает само** (см. ниже, то же
решение, что у обычной проверки) — кнопка только открывает страницу/ссылку в
браузере, ставит человек сам. Список — это ровно то, что лежит в GitHub Releases,
не более: если каких-то версий там нет (см. `docs/HANDOFF_1.11.0.md` про пустой
`GITHUB_TOKEN` — из-за него релизов линейки 1.11.x не существует), в списке их тоже
не будет, и это не повод считать приложение сломанным.

Откат версии физически выполняет **установщик**, не приложение: `installer/silentgate.iss`
уже умеет спрашивать про откат при установке файла со СТАРШЕЙ версией, чем стоит
(«Нет» по умолчанию, `/FORCEDOWNGRADE` для осознанного) — эта часть готова и кнопка
её не меняет.

## Признак беты у УЖЕ УСТАНОВЛЕННОЙ сборки (`AppInfo.channel`, 1.13.0)

Свойство самой сборки, а не ответа сервера: манифест приходит уже ПОСЛЕ того, как
человек бету поставил, а «О программе» обязано честно говорить, что у него за файл,
даже без единого сетевого запроса. Задаётся на сборке:

```
set SILENTGATE_CHANNEL=beta
build-exe.bat
```

(аналогично `build-apk.bat`). Значение уезжает в бинарник через
`--dart-define=SILENTGATE_CHANNEL=beta` → `AppInfo.channel`
(`String.fromEnvironment`). Обычная сборка переменную не задаёт вовсе — канал пуст,
`AppInfo.isBeta == false`. «О программе» дописывает «(бета)» к номеру версии, только
когда `AppInfo.isBeta` истинно.

## Поведение в приложении (без изменений с 0.9.x)

При запуске (если включено в настройках, `appUpdateCheck`) и по кнопке «Проверить»
приложение делает один запрос к текущему источнику. Если пришедшая версия **новее
текущей** — всплывает уведомление с кнопкой «Скачать», которая открывает ссылку в
браузере.

**Приложение НИЧЕГО не скачивает и не запускает само.** Осознанное решение:
установщик не подписан сертификатом, и самозапуск скачанного exe упирается в
SmartScreen и выглядит для антивирусов ровно как поведение зловреда. Пользователь
скачивает и ставит обновление сам.

Если источник недоступен — три исхода различимы (`UpdateCheckState`), а не два:
«обновление есть» / «у вас последняя версия» / «проверить не удалось» с причиной.
Смешивать «не удалось» с «последняя версия» нельзя — человек без сети получил бы
успокоительное вранье и перестал бы проверять вручную.
