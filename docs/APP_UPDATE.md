# Автообновление приложения

Как SilentGate узнаёт о новой версии себя. Не путать с обновлением **подписки** —
про него отдельный документ `SUBSCRIPTION_UPDATE.md`.

⚠️ Этот документ переписан в 1.13.0: прежняя редакция описывала один настраиваемый
эндпоинт («Эндпоинт версии» в настройках) — поле убрано ещё в 0.9.x, а документ этого
не отражал. Технический контракт серверной части — в `docs/APP_UPDATE_SERVER.md`,
здесь — как это устроено со стороны приложения.

⚠️ **С 1.14.0 приложение обновляется САМО** — скачивает, проверяет подпись и хэш,
ставит. Всё, что ниже в разделах про 1.13.0 сказано о «только ссылке», относится к
версиям до 1.14.0; актуальное поведение — раздел «Поведение в приложении». Первое
самообновление возможно только С 1.14.0: 1.13.x обновится до неё по-старому, ссылкой.

## Источники — два, канала — тоже два

| | Источник | Роль | Отдаёт беты? |
|---|---|---|---|
| 1 | GitHub Releases, `/releases/latest` | основной, стабильный канал | нет — `/latest` исключает пре-релизы по определению GitHub |
| 2 | `silentgate.lol/api/app-version` | запасной для (1) | нет |
| 1б | GitHub Releases, `/releases` (СПИСОК) | основной, **бета-канал** | да |
| 2б | `silentgate.lol/api/app-version-beta` | запасной для (1б) | да |

Запасные источники существуют не для красоты: у части пользователей `api.github.com`
не открывается вовсе (TLS перехватывается на стороне провайдера — воспроизведено в
чистой VM без VPN при живом `github.com`). Клиентом пользуются именно там, где
интернет фильтруют, поэтому «GitHub недоступен» здесь обычное дело, а не авария.
Порядок жёсткий: спрашиваем GitHub, при ЛЮБОМ его отказе — сайт; пока GitHub отвечает,
сайт не трогаем вовсе.

## Галочка «Получать бета-версии» (`AppSettings.betaChannel`, 1.13.0)

По умолчанию **выключена**. Меняет то, какой из четырёх источников выше
спрашивает `AppUpdate.check()` — на основной эндпоинт сайта
(`silentgate.lol/api/app-version`) она не влияет никак. С 1.14.0 она же решает, примет ли
приложение подписанный манифест с `"channel": "beta"` (см. «Поток»): без галочки такой
манифест отвергается как `channelMismatch`.

- **Выключена** — источники (1)/(2), ровно так же, как было всегда.
- **Включена** — источники (1б)/(2б): GitHub отдаёт СПИСОК релизов (`GET /releases`,
  без `/latest`) от новых к старым по дате публикации; первый элемент — это и есть
  «новейшее, включая пре-релизы», сравнение версий между элементами списка не
  требуется. Черновики (`draft: true`) отбрасываются на разборе — они не
  опубликованы, предлагать их как доступную версию нечестно.

⚠️ **Признака канала в ОСНОВНОМ манифесте намеренно нет.** Разговор возник из-за
1.12.0: сайт-агент выложил её как GitHub-пререлиз (`prerelease: true`,
`make_latest: false`) и в `/opt/updates/beta/`, но не тронул `/api/app-version` —
именно поэтому автообновление её никому не разослало. Если бы признак жил в
основном манифесте, включение поля на сервере само по себе разослало бы бету всем
подряд без их решения. Отдельный источник — единственный способ спросить о бете, не
трогая канал, которым пользуются все.

При найденном релизе UI показывает плашку «БЕТА» (`AppRelease.isBeta`), если ответ —
пре-релиз (`prerelease: true` у GitHub, поле `beta`/`channel` у сайта), и отдельную
строку про то, что это пре-релиз и автообновление такие версии не рассылает.

## Кнопка «Прежние версии» (1.13.0)

Список релизов (1б) уже запрашивается ради беты — тот же список годится и для отката:
`AppUpdate.fetchReleaseHistory()` отдаёт последние N релизов (версия + дата публикации
+ ссылка).

**1.14.0:** список живёт на экране «Обновления». Установленная копия на Windows может
поставить прежнюю версию сама: `AppUpdateController.offerRelease()` → та же закачка и
проверка подписи, что у обычного обновления → `install(allowDowngrade: true)`, то есть
установщик с `/FORCEDOWNGRADE`, — только после подтверждения человеком. Во всех
остальных случаях (Android, портативная копия и прочие из «Когда самообновление
недоступно») кнопка открывает страницу релиза, ставит человек сам.

Список — это ровно то, что лежит в GitHub Releases, не более: если каких-то версий там
нет (см. `docs/HANDOFF_1.11.0.md` про пустой `GITHUB_TOKEN` — из-за него релизов линейки
1.11.x не существует), в списке их тоже не будет, и это не повод считать приложение
сломанным. Релиз без подписанного манифеста (всё, что выпущено до 1.14.0) самим не
ставится — только ссылкой.

Откат физически выполняет **установщик**: `installer/silentgate.iss` при установке файла
со СТАРШЕЙ версией спрашивает («Нет» по умолчанию), в тихом режиме без `/FORCEDOWNGRADE`
отказывает. Приложение лишь передаёт этот ключ.

## Признак беты у УЖЕ УСТАНОВЛЕННОЙ сборки (`AppInfo.channel`, 1.13.0)

Свойство самой сборки, а не ответа сервера: манифест приходит уже ПОСЛЕ того, как
человек бету поставил, а «О программе» обязано честно говорить, что у него за файл,
даже без единого сетевого запроса. Задаётся на сборке:

```
set SILENTGATE_CHANNEL=beta
build-exe.bat
```

(аналогично `build-apk.bat`). Значение уезжает в бинарник через
`--dart-define=SILENTGATE_CHANNEL=beta` → `AppInfo.channel`
(`String.fromEnvironment`). Обычная сборка переменную не задаёт вовсе — канал пуст,
`AppInfo.isBeta == false`. «О программе» дописывает «(бета)» к номеру версии, только
когда `AppInfo.isBeta` истинно.

## Поведение в приложении (1.14.0: самообновление)

До 1.14.0 приложение при новой версии только открывало ссылку. Теперь оно само скачивает
установщик, проверяет его по **подписанному манифесту релиза** и ставит. Код:
`core/update/*` (разбор релиза, манифест, подпись, установщики),
`core/net/file_download.dart` (закачка), `state/app_update_controller.dart` (машина
состояний), экран — «Обновления» в настройках.

### Когда проверяется

- При запуске — если включено `AppSettings.appUpdateCheck`. Контроллер стартует, когда
  настройки прочитаны с диска (`SettingsController.whenLoaded`), а не при сборке дерева:
  иначе он решал бы по умолчаниям и мог качать установщик человеку, который автопроверку
  выключил. Провайдер — `appUpdateProvider` в `state/provider_wiring.dart`, `lazy: false`.
- По кнопке «Проверить сейчас» на экране «Обновления».

Исходов проверки три (`UpdateCheckState`), а не два: «обновление есть» / «у вас последняя
версия» / «проверить не удалось» с причиной. Смешивать «не удалось» с «последняя версия»
нельзя — человек без сети получил бы успокоительное вранье и перестал бы проверять вручную.
Отказ автопроверки на старте молчит (человек её не просил), отказ ручной — показывается.

Все запросы обновления — проверка, манифест, подпись, установщик — идут **напрямую**
(`findProxy = DIRECT`): умолчание Dart берёт прокси из окружения (`http_proxy`/`all_proxy`),
и проверка могла бы уйти через чужой прокси или через локальный порт нашего же ядра — и
упасть вместе с туннелем. User-Agent — `AppInfo.userAgent`; закачки (`downloadToFile`)
следуют редиректам сами и ставят его на каждом хопе.

### Три режима (`AppSettings.appUpdateMode`)

| Режим | Строка в JSON | Что делает с найденной версией |
|---|---|---|
| **Спрашивать** (умолчание) | `ask` | Показывает версию и заметки; ничего не качает, пока человек не нажмёт «Обновить». |
| **Автоматически** | `auto` | Качает и проверяет сам. Ставит сам, **только если VPN не активен** (подключено или подключается = активен). При активном VPN остаётся в «Готово к установке» и ставит, когда VPN отключат. |
| **Только сообщать** | `notify` | Ничего не качает; показывает ссылку на релиз, как до 1.14.0. |

- Неизвестное значение или отсутствие ключа — `ask`. Миграция: у старых настроек с
  `appUpdateNotesHidden: true` и без `appUpdateMode` — `notify`; старый ключ больше не
  пишется.
- **«Пропустить версию»** пишет её в `appUpdateSkippedVersion` и чистит скачанное. На старте
  пропущенная версия молчит; «Проверить сейчас» её показывает (её спросили). Вышла версия
  новее пропущенной — пропуск снимается сам.
- **«Позже»** ничего не удаляет и не запоминает: диалог не всплывает повторно в эту сессию, и
  режим `auto` не ставит сам по отключению VPN.
- Разрыв живого VPN — только с согласия человека (`install(forceQuit: true)` →
  `/FORCEQUIT`). Автоматика VPN не рвёт никогда.
- Перед установкой, которую человек не нажимал (режим `auto`, отложенная до отключения VPN),
  контроллер зовёт крючок `beforeUnattendedInstall` — место, где интерфейс предупреждает
  человека (окно почти всегда свёрнуто в трей, и иначе приложение просто исчезло бы без
  объяснений). ⚠️ На 24.09.2026 крючок интерфейсом ещё не назначен.

### Поток

Порядок жёсткий; **ни одного байта установщика до проверки подписи**. Любой отказ на
лестнице — фаза `failed` с названной причиной (`UpdateErrorKind`, для манифеста — ещё и
`ManifestRejection`), закачки нет.

1. **Проверка.** GitHub (`/releases/latest`, либо СПИСОК `/releases` при бета-галочке), при
   любом отказе — сайт (`/api/app-version[-beta]`). Из ответа берутся: версия; актив под
   платформу (сравнение по хвосту имени с вырезанной версией: Windows —
   `SilentGateSetup-<версия>.exe`, Android — `…-arm64-v8a.apk`); манифест и подпись по
   **точным** именам `SilentGate-<версия>.manifest.json` / `.manifest.sig`; размер актива.
   Не хватает хоть одного из пяти (адрес актива, имя, размер > 0, манифест, подпись) или
   адрес не проходит по схеме — `canSelfUpdate = false`, дальше только ссылка.
2. **Можно ли ставить самим** — `UpdateInstaller.capability()` (см. «Когда самообновление
   недоступно»). Нет — ссылка с объяснением.
3. **Имя актива** проверяется как имя файла: только `[A-Za-z0-9._-]`, не с точки, не длиннее
   200 — оно приходит из ответа сервера и подставляется в путь на диске.
4. **Манифест и подпись** качаются в память с потолком (64 КБ и 4 КБ).
5. **Подпись** — Ed25519 над БАЙТАМИ манифеста, ключ вшит в приложение
   (`UpdateSignature.verify`, никогда не бросает: мусор = `false`).
6. **Манифест** (`UpdateManifest.parse` → `validateManifest`), по порядку:
   `version` манифеста == версия РЕЛИЗА (`versionMismatch`) → канал `beta` допустим только
   при включённой бета-галочке (`channelMismatch`) → актив с ТОЧНО таким именем есть
   (`assetMissing`) → размер > 0 и sha256 — 64 hex (`malformed`).
7. **Закачка** (`downloadToFile`) в каталог закачек: размер и sha256 — ИЗ МАНИФЕСТА, а не из
   ответа релиза (расхождение пишется в журнал, верим манифесту). `Content-Length`
   сверяется с размером ДО тела, число принятых байт — после, потолок 600 МБ; sha256
   считается потоком; пишется `<имя>.part` и переименовывается только после всех проверок —
   после любой неудачи `.part` удалён, под настоящим именем файла нет. Фаза `ready`.
8. **Защита от отката.** Перед установкой версия предложения обязана быть новее нашей
   (`notNewer` иначе). Исключение одно — осознанный откат из «Прежних версий»
   (`allowDowngrade`).
9. **Повторная сверка хэша того же пути прямо перед запуском** (Windows — перед
   `Process.start`, Android — перед передачей системному установщику). Не совпал — запуск
   отменён.
10. **Установка.** Перед запуском пишется `updates/pending.json` (версия, время, путь
    установщика, путь журнала) — ДО запуска, потому что установщик закроет приложение через
    секунды. Не запустился — запись удаляется.
11. **Сверка при следующем старте** (`reconcileAfterStart`, файл удаляется всегда):
    - версия приложения == записанной → «Обновлено до <версия>», установщик и журнал
      удалены;
    - не совпала, записи меньше суток → карточка «Установка не завершилась» с хвостом
      журнала установщика (последние 40 строк / 4000 символов; журнал Inno — UTF-8 с BOM);
    - записи больше суток → итог не разбирается (`stale`).

    Затем `purgeStaging` чистит каталог закачек, оставляя файлы версии, установка которой
    не удалась, — их показывает «Показать журнал».

### Модель безопасности

- **Приватный ключ — только у владельца**: `signing/update_ed25519.key` (32-байтный seed в
  base64, каталог `signing/` в `.gitignore`), генерируется `app/tool/update_keygen.dart`.
  **Публичный зашит** константой `kUpdatePublicKeyBase64` в
  `core/update/update_pubkey.dart` и **не переопределяется ничем** — ни переменной
  окружения, ни настройками, ни тестовым override адреса. Подменить источник можно,
  подменить доверие — нет. Потеря приватного ключа = выпущенные сборки больше не примут ни
  одного обновления (см. `docs/CODE_SIGNING.md`).
- **Почему подпись, а не только SHA-256.** Хэш защищает от обрыва, а не от подмены: кто
  подменил файл на сервере, подменит и хэш рядом. Подпись ставится ключом, которого на
  сервере нет. Одна подпись на релиз (над манифестом), хэши — на все активы.
- **Replay / downgrade.** Подпись доказывает автора, а не релиз: честно подписанный манифест
  1.14.0, отданный вместо 1.14.1, — откат с валидной подписью. Ловится дважды: версия
  манифеста обязана равняться версии релиза, и ставится только версия новее установленной
  (кроме явного отката).
- **Точное имя актива**, не `contains`: `SilentGateSetup-1.14.1.exe` и
  `SilentGateSetup-1.14.1.exe.bak` — разные файлы.
- **TOCTOU.** Хэш при закачке говорит о файле, каким он был тогда; каталог закачек доступен
  на запись всему, что работает от имени пользователя. Поэтому тот же путь хэшируется ещё
  раз непосредственно перед запуском.
- **`http://` — только под тестовым override** (`isUpdateUrlAllowed` при разборе релиза и
  проверка схемы в контроллере). В боевом режиме — только `https://`; иные схемы — никогда.
  Под override `http` допустим потому, что целостность держит подпись, а не TLS.
- **Журнал без адресов.** Пишутся версии, размеры, фазы и причины; текст исключений
  проходит `scrubUrls`. Каталог закачек не входит в отчёт поддержки.
- **Windows: установщик — не наш ребёнок.** Аргументы списком, `runInShell: false`,
  `ProcessStartMode.detached`, в `CoreCleanup` не регистрируется: он обязан пережить наш
  выход.
- **Windows: возвышенная копия не ставит.** Установка per-user (`PrivilegesRequired=lowest`),
  путь берётся из HKCU, куда пользователь пишет сам; запуск установщика по этому пути из-под
  администратора превратил бы строку реестра в повышение прав.

### Windows: как запускается установщик

Каталог закачек — `%APPDATA%\SilentGate\updates\`. Командная строка (контракт 1.13.0 с
`installer/silentgate.iss`, `.iss` не менялся; литералы сверяет `test/installer_test.dart`,
читая оба файла):

```
SilentGateSetup-<версия>.exe /SILENT /SUPPRESSMSGBOXES /NORESTART /NOCANCEL [/FORCEQUIT] /DIR=<InstallLocation> /LOG=%APPDATA%\SilentGate\updates\install-<версия>.log [/FORCEDOWNGRADE]
```

- `/SILENT`, а не `/VERYSILENT`: человек видит полосу установки и понимает, почему
  приложение сейчас закроется.
- `/FORCEQUIT` — только после согласия на разрыв живого VPN. Без него установщик в тихом
  режиме при подключённом VPN **откажет** (строка `QuitBusySilent` в `.iss`), и отказ будет
  виден при следующем старте карточкой с журналом.
- `/FORCEDOWNGRADE` — только из «Прежних версий». Без него тихий режим поверх более новой
  версии отказывает (`NewerInstalledSilent`).
- `/DIR=` — `InstallLocation` из
  `HKCU\Software\Microsoft\Windows\CurrentVersion\Uninstall\{B7F3B2A1-5C2E-4E7A-9F1D-51E4C0DE0001}_is1`
  **без хвостового `\`**: Dart при пробеле в аргументе удваивает хвостовые слэши по правилам
  C-рантайма, а Inno разбирает строку по правилам Delphi и получил бы каталог с `\\`.
  Кавычек в аргументах нет — их расставляет `Process.start`.
- Вывод `reg query` читается байтами и раскодируется из OEM-страницы
  (`MultiByteToWideChar(CP_OEMCP)`): иначе путь с кириллицей в имени пользователя
  превращался в мусор, и каждый русский пользователь получал бы `locationMismatch`.
- Приложение установщик закрывает сам (мьютекс, `WaitForMutexGone`), после тихой установки
  поднимает обратно (`Check: ShouldRelaunch`).

### Android: чем отличается

- **Тихой установки нет** — без root её не бывает. Приложение передаёт APK системному
  установщику (`ACTION_VIEW`, `application/vnd.android.package-archive`, FileProvider,
  `FLAG_GRANT_READ_URI_PERMISSION`), и человек **всегда** видит системное окно согласия.
  Итог узнаёт следующий запуск по `pending.json`; журнала у системного установщика нет,
  поэтому у отказа нет и хвоста журнала.
- **Разрешение.** В манифесте — `REQUEST_INSTALL_PACKAGES`. На API 26+ нужна ещё галочка
  пользователя «Разрешить из этого источника» (`canRequestPackageInstalls()`); нет — фаза
  `needsPermission`, кнопка открывает `ACTION_MANAGE_UNKNOWN_APP_SOURCES` с `package:` URI
  (запасной — «О приложении»), после возврата установка повторяется. На API 24–25 отдельного
  разрешения нет (общесистемный тумблер «Неизвестные источники», его спрашивает сам
  системный установщик); кнопка ведёт в «Безопасность».
- **Каталог закачек — `cacheDir/updates/`**, а не каталог данных: установщику нужен
  `content://`-доступ, и FileProvider открыт ровно на этот каталог (`<cache-path
  name="updates">`). `files/SilentGate` наружу не открывается — там подписки с токенами.
  Kotlin (`PlatformChannels.installApk`) отвергает путь вне `cacheDir/updates/`.
- `capability()` всегда `ready`: портативных и неустановленных копий на Android не бывает.
- **Откат — только ссылкой.** Система не ставит пакет с меньшим versionCode поверх большего,
  поэтому `/FORCEDOWNGRADE`-аналога нет.
- **ABI.** У x86_64 (эмулятор, TEST-ONLY) versionCode 4000+, у arm64 — 2000+: чужая ABI
  выглядела бы «новее», но не запустилась бы. Таблица хвостов — `androidAssetHintForAbi`
  (`arm64-v8a` → `-arm64-v8a.apk`, `x86_64` → `-x86_64.apk`, прочие ABI — ничего).
  ⚠️ **На 24.09.2026 ABI устройства в проверку не передаётся**: `AppUpdate.check` берёт
  `kPlatformAssetHint` без ABI, то есть на Android всегда `arm64-v8a.apk` — эмулятор x86_64
  получит телефонный APK, и система его не поставит.

### Когда самообновление недоступно

Во всех случаях ниже фаза `linkOnly` с причиной (`LinkOnlyReason`): приложение показывает
ссылку на релиз и объясняет, почему не ставит само. Проверка возможности (`capability()`)
идёт перед закачкой — в режиме «спрашивать» ссылка появляется после «Обновить».

| Причина | Когда | Что делать человеку |
|---|---|---|
| `notifyOnly` | выбран режим «Только сообщать» | ставить самому по ссылке либо сменить режим |
| `noSelfUpdate` | в релизе нет манифеста, подписи, актива под платформу или размера (так выглядят все релизы до 1.14.0) | ставить самому по ссылке |
| `portable` | рядом с exe лежит `portable.txt` | распаковать новый архив поверх, `sg-data\` не трогая |
| `isolated` | задан `SILENTGATE_PORT_OFFSET` — изолированная копия не должна трогать установленную | обновлять установленную копию |
| `notInstalled` | записи Inno в HKCU нет (запуск из архива или папки сборки) | поставить установщиком |
| `locationMismatch` | установка есть, но exe запущен из другого каталога | запускать установленную копию |
| `elevated` | приложение запущено от администратора | запустить без повышения |
| `unsupported` | платформа без самообновления (не Windows и не Android) | ставить самому |

На Android из этого списка возможны только `notifyOnly` и `noSelfUpdate`; отсутствие
разрешения на установку — не `linkOnly`, а отдельная фаза `needsPermission` (см. выше).

### Почему SmartScreen не мешает (и что остаётся)

Прежнее решение «не скачивать и не запускать» стояло на том, что самозапуск
неподписанного exe упрётся в SmartScreen. Это не так, и вот почему.

- SmartScreen проверяет файл по **Mark-of-the-Web** — альтернативному потоку
  `Zone.Identifier`. Его пишет программа, скачавшая файл: браузер, Проводник при
  распаковке, почтовый клиент. `HttpClient` Dart зону не пишет, поэтому у скачанного
  приложением установщика метки нет.
- Запуск через `Process.start` (`CreateProcess`) проверку репутации SmartScreen не
  вызывает — её вызывает оболочка (`ShellExecute`) для файлов с меткой.
- Установка per-user (`PrivilegesRequired=lowest`) — окна UAC тоже нет.
- **Что остаётся и что мы принимаем:** эвристика антивирусов («программа скачала и
  запустила exe») может срабатывать; подпись Authenticode снизила бы её, но её нет
  (`docs/CODE_SIGNING.md`). Если на машине включён Smart App Control Windows 11, он
  проверяет неподписанные exe независимо от метки и может заблокировать установщик —
  тогда установка не состоится, и следующий старт покажет карточку «Установка не
  завершилась».

### Стенд: тестовый override источника

Чтобы прогнать поток целиком (проверка → закачка → подпись → установка) в VM `SG-Test` и
эмуляторе `sg-test`, не выкладывая тестовый релиз на GitHub, базу API можно подменить:

- **Windows** — переменная окружения `SILENTGATE_UPDATE_API=<база>` (например,
  `http://192.0.2.10:8000`), читается при первом обращении.
- **Android** — файл `<filesDir>/SilentGate/update_api.txt` (первая непустая строка;
  хвостовой перевод строки допустим). `run-as` на релизном APK не работает, поэтому — через
  `adb root` на образе без Google Play (`sg-test` — такой), после первого запуска приложения
  (каталог `SilentGate` создаёт оно). Файл, созданный root-ом, приложению не прочитать —
  владельца и SELinux-метку берём у каталога:
  ```
  adb reverse tcp:8000 tcp:8000
  adb root
  adb shell 'D=/data/data/lol.silentgate/files/SilentGate; F=$D/update_api.txt; echo http://127.0.0.1:8000 > $F; chown $(stat -c %u:%g $D) $F; chcon $(ls -Zd $D | cut -d" " -f1) $F'
  ```
  (Команды — набросок под план живого прогона 1.14.0, на стенде ещё не выполнялись.)

База без хвостового `/`, только `http(s)` с хостом; мусор в значении override не включает.
Сервер стенда отдаёт те же пути, что GitHub: `/repos/Solat228/silentgate/releases/latest`
(и `/releases` для бета-канала и «Прежних версий») с `browser_download_url`, указывающими на
файлы на том же сервере, плюс сами файлы — актив, `.manifest.json`, `.manifest.sig`.
Манифест подписывается настоящим ключом (`tool/sign_release.dart`): override меняет только
адрес.

Под override: `http://` допустим для закачек, в журнал пишется предупреждение, на экране
«Обновления» — плашка «Источник подменён».

⚠️ Что override НЕ подменяет: запасной источник — сайт (`silentgate.lol/api/app-version`,
`-beta`) спрашивается по боевому адресу. Если сервер стенда не ответил, проверка уйдёт на
настоящий сайт.

⚠️ **Android, на 24.09.2026:** признак override контроллер получает при создании
(`overridden: kUpdateApiOverridden` в `provider_wiring.dart`), а на Android файл читается
позже, при первой проверке (`AppUpdate.loadApiOverride`). Поэтому на Android контроллер
считает источник неподменённым: `http://`-адреса стенда отвергаются как `insecureUrl`, плашки
нет. До починки — стенд на `https://` либо чтение файла до создания контроллера.

Снять override после прогона: удалить переменную окружения / файл.
