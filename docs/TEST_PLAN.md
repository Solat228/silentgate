# План тестирования SilentGate (Windows)

Как проверять релиз. Разделено на: **A. Автоматическое** (гоняется без VPN),
**B. Статическая валидация конфигов**, **C. Ручное функциональное** (по областям,
с шагами и ожидаемым результатом), **D. Матрица окружений**, **E. Живой тест
подключения** (за тестировщиком — реальные серверы).

> Правило: код-агент VPN сам НЕ включает. Всё, что требует реального туннеля/
> подключения (раздел E и пометки 🔴), проверяет человек на тестовой машине.

Легенда приоритетов: 🔴 критично · 🟠 важно · 🟢 обычное.

---

## A. Автоматическое (CI / локально, без VPN)

Из папки `app` (по «грязному» пути `I:\!…` тоже работает):

```
flutter analyze            # ожидаем: 0 errors, 0 warnings
flutter test               # ожидаем: All tests passed (≈156, ~3 diag-скипа)
flutter test --run-skipped # diag-тесты (нужен изолированный APPDATA, см. ниже)
```

Что покрыто юнит-тестами (не полный список):
- Парсер ссылок, share-link round-trip, XRAY_JSON, override.
- Генерация конфига sing-box: DNS-final=dns-proxy (нет утечки в onlySelected),
  валидация exclude-CIDR, санитайз custom-DNS, split-правила (app/site/port), блок.
- NetworkWatcher.fingerprintOf: временные IPv6 (/64), Teredo, свой TUN, виртуальные
  адаптеры 172.16/12 — не считаются сменой сети; реальный LAN — считается.
- i18n: паритет ВСЕХ `app_*.arb` с `ru` (ключи/значения/плейсхолдеры), сортировка
  меню языков, `autoTextDirection` (латиница→LTR, арабский/фарси→RTL).
- Аватарка: gradientFor детерминизм, logoUrl round-trip.
- Настройки/пинг/автоконфиг round-trip, HWID header-safe, subscription логотип
  (MockClient, cookie-протокол), огромный title/announce.

Diag-тесты (сеть + ИЗОЛИРОВАННЫЙ `%APPDATA%`; папка данных должна содержать
`scratchpad`, иначе тест откажется писать): `diag_live_test`, `diag_override_ping_test`,
`diag_subscription`, `diag_multi_sub_test`, `diag_panel_json_test`.

## B. Статическая валидация конфигов (без подъёма туннеля)

```
dart run tool/emit_config.dart "<share-link>" > sample.json
../engine/windows/bin/xray.exe run -test -c sample.json          # проверка Xray-конфига
dart run tool/emit_singbox.dart [all|only|except] [system|gvisor|mixed] > tun.json
../engine/windows/bin/sing-box.exe check -c tun.json              # проверка TUN-конфига
dart run tool/emit_hysteria2.dart --harness --links f.txt > h.json
../engine/windows/bin/sing-box.exe check -c h.json               # hysteria2
dart run tool/diag_subscription.dart <url> --emit-all <dir>       # что реально шлёт панель
```
Ожидаем: `xray -test` и `sing-box check` — без ошибок на всех комбинациях split×стек×DNS.

## C. Ручное функциональное

### C1. Импорт и подписки 🔴
1. Импорт по URL подписки → серверы появились, карточка заполнена (название,
   трафик, срок).
2. Импорт одиночной ссылки (`vless://`, `hysteria2://`) → добавился ЗАКРЕПЛЁННЫЙ
   сервер, из подписки ничего не пропало.
3. Импорт полного JSON из буфера → кастом-сервер `📋 Импортированный конфиг`.
4. «Обновить подписку» → сводка «N серверов · +добавлено · −удалено».
5. Мульти-подписки: добавить вторую → переключатель в карточке; переключение
   меняет список/карточку/аватарку.
6. Удалить активную подписку → переключение на оставшуюся; вопрос про пины.
7. Перезапуск приложения → всё восстановилось (серверы, выбор, пины, override).
8. Истёкшая подписка (notice-серверы `0.0.0.0:1`) → плитка без пинга/connect,
   кнопки «Обновить»/«Скопировать».

### C2. Аватарка (логотип) 🟠
1. Импорт подписки с логотипом (панель отдаёт `x-logo-url` или брендинг
   `/assets/.app-config-v2.json` по cookie) → логотип появился.
2. Импорт ДРУГОЙ подписки → НЕ мелькает логотип прежней (её кэш или буква).
3. Обновление с тем же логотипом → картинка не мигает (keep-if-unchanged).
4. Нет логотипа → цветной кружок с буквой (градиент детерминирован по названию).
5. Логотип тянется ТОЛЬКО при импорте/обновлении (на старте в фоне — нет).

### C3. Пинг 🟠
1. «Пинг серверов» → TCP до всех; молчащие = серым «n/a»/таймаут.
2. С галочкой «Проверять работоспособность» → фаза 2 (GET/HEAD через прокси);
   Reality без проксирования → «отвечает, но не проксирует».
3. hysteria2 (UDP/QUIC) → сразу фаза 2 (TCP не мерится).
4. Ход — карточкой слева снизу; итог висит 10 с.

### C4. Раздельное туннелирование 🔴 (нужен TUN — раздел E)
Статически (UI + конфиг) можно проверить и без подключения:
1. Режимы all / onlySelected / exceptSelected переключаются.
2. **Режим «Все — через VPN»:** ранее выбранные правила НЕ теряются (переключить
   в onlySelected и обратно — правила на месте); превью показывает простую схему
   💻 → 🔒 VPN → 🌐 без «прямых»/«блок» строк.
3. Приложение: добавить из списка запущенных / выбрать exe; иконка exe реальная
   (не путается Chrome↔Telegram); byName/byPath; галочка вкл/выкл.
4. Сайт: домен + порт; поддомены деревом (example.com / sub.example.com); действие
   Туннель/Прямо/Блок.
5. Схема маршрута соответствует правилам (по действиям).
6. `sing-box check` для сгенерированного конфига (раздел B).

### C5. Локализация (i18n) 🔴 — 10 языков + RTL
1. Настройки → кнопка языка (флаг + значок перевода) → меню **отсортировано по
   алфавиту (Arabic, Chinese, English, French, German, Persian, Portuguese,
   Russian, Spanish, Turkish)** + пункт «Как в системе».
2. Выбрать КАЖДЫЙ из 10 языков → весь интерфейс переводится (не только заголовки):
   настройки, главный экран, карточка, split, TUN-настройки, инфо о сервере,
   автонастройка, диалоги, «!»-подсказки, трей.
3. «Как в системе» → язык берётся из ЯЗЫКА WINDOWS (проверить на локализованной
   Windows); неподдерживаемый язык системы → **английский** (не русский/арабский).
4. **RTL (العربية / فارسی):**
   - Раскладка зеркалится (заголовки справа, стрелки/отступы).
   - **Имена серверов и технический текст НЕ зеркалятся** (латиница слева-направо):
     имена/адреса/IP, URL, конфиг/JSON, HWID/User-Agent, пинг/скорость, пути,
     строки логов, scheme-URI, блок Response-Rules.
   - Провайдерский текст (название подписки, объявление, notice) — направление ПО
     СОДЕРЖИМОМУ: латинское название слева-направо, арабское объявление — справа-налево.
5. Смена языка мгновенная (без перезапуска). Значок-флаг в кнопке = текущему языку.

### C6. Отчёт для техподдержки 🟠
1. Настройки → «Написать в поддержку» → окно; до нажатия кнопки НИЧЕГО не создаётся
   и не открывается.
2. «Сгенерировать лог» → СНАЧАЛА папка (файл выделен), пауза, ПОТОМ сам txt.
3. **Шапка отчёта на языке интерфейса** (заголовок, «ОПИШИТЕ ПРОБЛЕМУ», поля,
   примечание); техническая часть — как есть.
4. В отчёте НЕТ паролей/токена; URL подписки замаскирован.
5. Меню «кому отправить»: «(Название сервиса)» из подписки + «(Разработчик клиента)».
6. Редирект: есть Telegram Desktop → открылся он (`tg://`), иначе браузер.

### C7. Информация о сервере 🟢
ПКМ по серверу → «Информация»: внешний IP/гео через сервер и без VPN, провайдер,
скорость (Cloudflare, вручную). Меряется проброс-харнессом — **VPN не включается**.

### C8. Настройки / прочее 🟢
1. Тема: системная/светлая/тёмная.
2. Трей: крестик → сворачивание (с вопросом) / полное закрытие; диалог при активном
   VPN; выход из трея гасит ядра.
3. URL-схемы: `silentgate://connect|disconnect|toggle|update|import?url=…` работают;
   сноска «Для владельца панели» внизу, кнопка «Скопировать блок».
4. Проверка обновлений приложения (только уведомление + ссылка, без автозагрузки).
5. Сеть: «Восстановить сеть», «Проверить помехи».

|---|---|
| ОС | Windows 10, Windows 11 |

## E. Живой тест подключения 🔴 (реальные серверы — за тестировщиком)

> Требует включения VPN. Перед TUN закрыть другие VPN/TUN-клиенты (Happ, v2rayTun) —
> два TUN-адаптера дерутся за маршрут.

### E1. Системный прокси
1. Connect → статус «Подключено», системный прокси прописан (WinINET).
2. Внешний IP сменился (проверить в браузере).
3. Disconnect во время «Подключение…» → прокси НЕ остаётся прописанным, статус не
   застревает на «Подключено» (#4); отмена не превращается в «Ошибка» (#6).
4. Disconnect → прокси снят, IP вернулся.

### E2. TUN (полный туннель)
1. Первое включение TUN → диалог, один UAC → задача Планировщика создана; дальше
   старт БЕЗ UAC.
2. Connect → адаптер `silentgate-tun` поднялся; весь трафик (вкл. UDP) идёт через VPN.
3. Автоподбор (стек/MTU): при сбое перебирает комбинации; рабочая сохраняется и
   пробуется первой.
4. **Отмена во время автоподбора** → перебор прекращается, туннель НЕ поднимается
   после «Отключить» (#5).
5. **DNS не течёт:** в режиме onlySelected DNS затуннелированных приложений идёт
   через VPN (проверить, что censorship-домен резолвится через туннель, а не ISP).
6. **Отдельный админ (#7):** на учётке, где UAC-админ — ДРУГОЙ пользователь, TUN
   поднимается по ПРАВИЛЬНОМУ конфигу (не пустому). Проверить лог sing-box.
7. **Частое переподключение (#8):** быстро connect/disconnect несколько раз подряд →
   каждый старт срабатывает (задача не «теряет» запуск).
8. **Docker/WSL (#10):** запустить Docker/WSL, подключиться, затем start/stop
   контейнера → НЕТ ложного цикла переподключений (в `app.log` нет «Сеть изменилась»
   каждые ~20 с).
9. Битый CIDR в «исключить подсети» (напр. `10.0.0.0/33`) → туннель ВСЁ РАВНО
   поднимается (битый CIDR отброшен), а не висит ~2 минуты.
10. Kill switch: между попытками восстановления трафик НЕ течёт мимо VPN.
11. Смена сети (Wi-Fi↔кабель, сон/пробуждение) → авто-переподключение без цикла.

### E3. Hysteria2
Сервер с `hysteria2://` (порт-хоппинг/обфускация) поднимается через sing-box на тех
же портах 10808/10809; системный прокси/TUN не знают, кто внизу.

### E4. Установщик
1. Inno Setup: установка → приложение в `%APPDATA%\SilentGate`, ярлык, url-схема.
2. Удаление → `--cleanup` (задача Планировщика удалена, прокси снят, ядра погашены).
3. (Опц.) Подпись: собрать с `SIGN_PFX`/`SIGN_THUMBPRINT` → `signtool verify /pa`
   проходит; без сертификата шаг молча пропущен (`docs/CODE_SIGNING.md`).
