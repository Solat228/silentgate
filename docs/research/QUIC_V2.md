# QUIC v2 для hysteria2 и автоматический выбор ядра — оценка

Дата: 24.09.2026. Статус: **оценка, решение за владельцем.** Кода по этому документу пока нет.

Повод — заявка агента панели в `HANDOFF.md` от 23.09.2026. Замеры FOCI 2026 (три точки в России)
показали, что ТСПУ расшифровывает QUIC Initial версии 1 и читает имя сайта из ClientHello. QUIC v2
(RFC 9369) при этом **не фильтруется**: разбор у ТСПУ привязан к номеру версии v1.

## 1. Что у нас сейчас

| Где | Кто поднимает hysteria2 | Версия ядра | Бинарник |
|---|---|---|---|
| Windows | sing-box, отдельным процессом | 1.11.15 | стоковый `engine/windows/bin/sing-box.exe` |
| Android | sing-box внутри `libcores.so` | 1.13.14 (+ наш патч sing-tun) | собираем сами, `C:\dev\android\src\cores` |

Ядро выбирается **автоматически, по протоколу сервера** (`VpnServer.core`): hysteria2 → sing-box,
всё остальное → Xray. Руками ядро не переключается и переключаться не должно: человек не знает,
какое ядро умеет какой протокол, а ошибка выбора даёт просто «не подключается».

Попутная находка: **наш Xray 26.3.27 тоже умеет hysteria** (`transport/internet/hysteria`) и
несёт семейство масок `finalmask` — `salamander`, `noise`, `sudoku`, `xdns`, `xicmp`, `mkcp`,
`header`, `fragment`, `quic`. То есть второе ядро для hysteria2 — сложившаяся архитектура, а не
необходимость (см. раздел 5).

## 2. Почему сегодня всегда v1

Проверено по исходникам тех версий, что мы реально собираем:

- sing-box → `github.com/sagernet/sing-quic v0.6.1`, `hysteria2/client.go:73`: `quic.Config{...}`
  собирается **без поля `Versions`**.
- quic-go (`sagernet/quic-go v0.59.0-sing-box-mod.4`, `internal/protocol/version.go:32`):
  `SupportedVersions = []Version{Version1, Version2}`, пустой `Versions` берётся отсюда, а клиент
  начинает рукопожатие с `Versions[0]` (`transport.go:263`) — то есть с **v1**.
- Xray (`transport/internet/hysteria/dialer.go:85`) — то же самое, свой форк `apernet/quic-go`
  с тем же списком `[v1, v2]` по умолчанию.

Наружу (в JSON-конфиг) версию QUIC не выводит ни одно из двух ядер. Формат подписки её тоже не
передаёт (ни Remnawave, ни ссылка `hy2://`).

Сервер: входящие hysteria2 на нодах построены на quic-go и тоже без `Versions`, значит по
умолчанию **принимают обе версии**. Это вывод по коду; живьём не проверено — агент панели
предлагал замер за час, он понадобится перед включением.

## 3. Что нужно, чтобы клиент ходил по v2

**Патч ядра — маленький:** в `quic.Config` клиента поставить `Versions: []quic.Version{Version2,
Version1}`. Порядок важен: v2 первым, v1 запасным.

- Сервер знает v2 → рукопожатие сразу по v2, лишних пакетов нет.
- Сервер не знает v2 → отвечает Version Negotiation, quic-go сам переходит на v1. Цена — одна
  лишняя поездка туда-обратно, и только при подключении.
- Промежуточное звено **молча выбрасывает** незнакомую версию → таймаут рукопожатия. Это
  единственный плохой случай, его закрывает логика в приложении (раздел 4).

**Где патчить:**

| Платформа | Что сделать | Трудоёмкость |
|---|---|---|
| Android | патч в `sing-quic` (как уже сделано с `sing-tun`, `engine/android/*.patch`) + `replace` в `go.mod` + пересборка `cores.aar` | низкая: механизм отлажен 20.09, сборка ~1 мин |
| Windows | собирать `sing-box.exe` самим (сейчас стоковый бинарник) либо увести hysteria2 на Xray и патчить `apernet/quic-go` | средняя: нужен свой конвейер сборки ядра под Windows, `gosdk` на машине есть |

Оговорка из PR `apernet/hysteria#1673`: при v2 у **hysteria-go** выключается подделка отпечатка
Chrome. К нам это напрямую не относится — у нас не hysteria-go. Нужно отдельно проверить, как
sing-box/Xray строят TLS внутри QUIC и не изменится ли от смены версии отпечаток Initial; в
этом документе не проверено.

## 4. Как сделать это автоматическим, без переключателя

Владелец поставил планку: всё должно работать **само и лучше, чем если бы человек перебирал
руками**, но **не должно выглядеть как сканер сети**. Для QUIC v2 это решается так:

1. **По умолчанию `[v2, v1]`** — без настройки. Там, где v2 проходит, человек ничего не заметит,
   кроме того, что hysteria2 перестала отваливаться.
2. **Память по серверу.** Если рукопожатие по v2 упёрлось в таймаут, а повтор по чистому v1
   прошёл — запоминаем для этого сервера «только v1» на сутки (как `tun_tuning.json` запоминает
   рабочий стек TUN). Следующее подключение сразу идёт рабочим путём, без повторной задержки.
3. **Не сканер.** Запасной путь — не больше одной попытки на подключение и только к серверу,
   который человек выбрал сам. Никакого перебора портов или адресов, никаких фоновых проб
   «на всякий случай».

Ручной переключатель можно оставить в разделе «для опытных», но только как принудительное
значение поверх автоматики, а не вместо неё.

## 5. Шире: «умный автоподбор» вместо ручного перебора

То же правило стоит применить ко всем «ручкам», которые сейчас выбирают руками либо
«Автонастройка» перебором:

| Ручка | Сейчас | Предлагаемая автоматика |
|---|---|---|
| Ядро | по протоколу, автоматически | так и оставить |
| Версия QUIC | всегда v1 | `[v2, v1]` + память по серверу (раздел 4) |
| Отпечаток TLS (`fp`) | из подписки как есть; вариация — через «Автонастройку» | как есть: панель ставит отпечатки намеренно (опыт 23.09), клиент не должен их подменять |
| Фрагментация ClientHello | вариации «Автонастройки» | кандидат на автоматический запасной путь при повторяющемся обрыве рукопожатия |
| salamander / finalmask | не используется | только когда панель начнёт отдавать `finalMask` в хосте — применять как есть |
| Обход DPI для «Прямо» | внешний zapret | в sing-box 1.12+ у действия `route` есть `tls_fragment` / `tls_record_fragment` — кандидат на встроенный запасной путь для прямого трафика |

Общие правила для всей автоматики:

- память «что сработало» — по серверу, с истечением срока, чтобы вернуться к лучшему варианту;
- запасной вариант — только к своему серверу, не больше одного-двух шагов на подключение;
- в журнал — какой вариант выбран и почему, иначе обрыв потом не разобрать.
