## 0. Коротко

1. **Salamander у hysteria2 клиент уже умеет** (оба sing-box), но **из XRAY_JSON его не прочтёт**:
   панель на Xray 26.x кладёт маску в `streamSettings.finalmask.udp`, а наш разбор ищет
   `hysteriaSettings.obfs`. Включит панель — наши hy2-серверы молча перестанут подключаться. Правка
   маленькая, делать до того, как панель переключит хост.
2. **Форма `finalmask`, которую описал агент панели, не совпадает с ядром** (`udpmasks`, пароль на
   верхнем уровне, `paddingMin/Max`). Xray такую форму **принимает с «Configuration OK» и молча
   игнорирует** — проверено. Нужен настоящий образец из выдачи панели.
3. **Остальное семейство finalmask, кроме `fragment` и `noise`, требует ноды.** Ни `fragment`, ни
   `noise` нам сейчас ничего нового не дают.
4. **Самый весомый рычаг клиента — не маска, а число TLS-рукопожатий.** По описанию эвристики ТСПУ
   (июнь 2026) больше трёх одновременных рукопожатий к одному SNI за 60 с «замораживают» TLS на 120 с,
   смена отпечатка после этого — на 600 с. Наши пинг, проверка сервисов и «Автонастройка» делают
   такие всплески сами. Это гипотеза, но дешёвая в проверке и в лечении.
5. **Отпечаток: убрать `randomized` из перебора** (подтверждённый баг Xray #6714), дефолт `chrome` в
   автонастройке — пересмотреть.
6. **`tls_fragment` для «Прямо» есть на Android уже сейчас** (sing-box 1.13.14), на Windows — только
   после перехода на 1.13.
7. **Port knocking / SPA — не делать сейчас.** REALITY уже отвечает на активные пробы чужим сайтом,
   тишину на UDP даёт salamander без демона, а стоковые клиенты стучать не умеют.
8. **Windows-Xray 26.3.27 отстаёт от Android и нод** — это предпосылка почти ко всему выше.

## 2. Какого противника касается

Маскировка работает против **сетевого** наблюдателя, и у него три разных приёма:

1. **Пассивный разбор рукопожатия** — SNI, JA3/JA4, подсеть адреса, число соединений. Здесь клиент
   решает много: отпечаток, фрагментация, темп рукопожатий.
2. **Активное прощупывание** — сканер шлёт SYN и ClientHello. Здесь решает сервер: REALITY отдаёт
   сайт-донор, salamander молчит, SPA держит порт закрытым. Клиенту остаётся уметь то, что включил сервер.
3. **Опознание протокола по форме UDP** (QUIC Initial v1 разбирается, v2 нет — `QUIC_V2.md`).

Против приложения-шпиона на том же телефоне ничего из этого не помогает (`VPN_DETECTION.md`,
`rejected-approaches` → RKN-hardening).

## 3. Техники по одной

### 3.1 Salamander (obfs у hysteria2)

**Что это.** Каждый UDP-датаграм перемешивается ключом из пароля и соли; пакет с неверным паролем
сервер выбрасывает без ответа — для сканера порт неотличим от закрытого. Цена: «Enabling obfuscation will
make your server incompatible with standard QUIC connections and it will no longer function as a valid
HTTP/3 server» [док: hysteria]. Попутно пропадает QUIC Initial, из которого ТСПУ читает SNI, — **для
такого входящего вопрос QUIC v2 снимается сам** (разбирать нечего ни в v1, ни в v2).

**Сервер.** Настройка входящего в панели. На нодах Xray 26.7.28 — маска `salamander` в `finalmask.udp`
[код: `infra/conf/transport_finalmask.go:80`]. Все клиенты этого хоста обязаны знать пароль, отката нет.

**Клиент.** sing-box 1.11.15 и 1.13.14: `obfs.type = salamander` [check, код]. Строитель есть.

**⚠️ Дыра в разборе XRAY_JSON.** `_fromHysteria` (`xray_json_subscription.dart:447-449`) берёт
`hysteriaSettings.obfs` / `obfsPassword`. В Xray с 26.3.27 obfs у hysteria живёт не там, а в
`streamSettings.finalmask.udp[] = {"type": "salamander", "settings": {"password": …}}` [код,
релиз 26.3.27: «Hysteria 2 inbound & transport (supports … Salamander finalmask)»]. Панель, включив
salamander, отдаст его именно так → наш парсер его не увидит → sing-box пойдёт без obfs → сервер молча
выбросит пакеты → «не подключается», без единой ошибки в журнале.

**⚠️ Форма из записи панели не та, что понимает ядро.** Агент панели написал `udpmasks`/`tcpmasks` и
элемент `{"type":"salamander","password":…,"paddingMin":…,"paddingMax":…}`. В исходниках Xray
[код: `transport_finalmask.go:862-910`]: ключи `tcp` / `udp`, параметры — во вложенном `settings`, у
salamander параметры `password` и `packetSize` (`paddingMin/Max` — это поля `sudoku`). Проверка
настоящим Windows-ядром [check]:

| Конфиг | `xray run -test` 26.3.27 |
|---|---|
| `finalmask.udp[{type: salamander, settings: {password}}]` на hysteria | Configuration OK |
| форма из записи панели (`udpmasks`, пароль сверху) | **Configuration OK — поля молча проигнорированы** |
| неизвестный тип маски `nosuchmask` | отказ: `unknown config id` |
| `salamander` в `finalmask.tcp` | отказ: `unknown config id: salamander` |
| `packetSize: "0-4000"` (заведомо неверный) | Configuration OK — поля в 26.3.27 ещё нет |

То есть **`-test` не ловит опечатку в ключе** (тот же класс, что `sing-box check` с чужими полями).
Форму берём только из настоящей выдачи панели.

**Gecko** (salamander + нарезка рукопожатия, `packetSize`) — в Xray с 29.05.2026 (#6198) [релиз]: у
Android-сборки есть, у Windows 26.3.27 нет, **в sing-box 1.13.14 нет вовсе** [код: в
`protocol/hysteria2` только `ObfsTypeSalamander`]. Наш hy2 идёт через sing-box → gecko нам недоступен.
Если панель включит gecko — наш клиент к такому хосту не подключится.

**Трудоёмкость.** Разбор `finalmask.udp` → `VpnServer.obfs/obfsPassword` + тест на образце панели:
часы, обе платформы сразу (Dart). Ядра не трогаем.

**Риск.** Ошибка пароля = полная тишина. Заметность: вместо QUIC — «случайный UDP» высокой энтропии; это
тоже признак, и у части операторов, по слухам, UDP за рубеж режется целиком [сообщество, не проверено].

**Рекомендация: встроить сейчас** — только разбор (и страж: salamander из XRAY_JSON доезжает до
sing-box). Включение — решение панели; тестовый хост с salamander и без мы у панели уже просили 24.09.

### 3.2 Xray finalmask — всё семейство

«Последний слой»: маски применяются к сырым TCP-потокам / UDP-датаграммам под транспортом. Появился в
26.x; в 26.3.27 «все прокси-потоки Xray могут идти через Finalmask» [релиз 26.3.27].

| Маска | Слой | Нужна ли нода | Windows 26.3.27 | Android-сборка | Польза нам |
|---|---|---|---|---|---|
| `fragment` | TCP | **нет** (режет запись на клиенте) | есть [check] | есть | та же фрагментация, что у нас есть, без лишнего outbound (§3.3) |
| `noise` | UDP | **нет** (мусорные датаграммы перед первым пакетом; сервер их выбрасывает) [код: `finalmask/noise/conn.go`] | есть | есть | нет: наш UDP к серверу — это hy2, а он идёт через sing-box |
| `salamander` | UDP | да | есть (без `packetSize`) | есть (+gecko) | только если hy2 поднимает Xray (§3.1, §3.9) |
| `header-custom`, `mkcp-legacy` | TCP/UDP | да | header-custom есть, mkcp-legacy нет | есть | — |
| `sudoku` | TCP/UDP | да | есть | есть | отложено |
| `xmc` (Minecraft) | TCP | да | **нет** (11.07.2026) | есть | отложено |
| `xdns`, `xicmp` | UDP | да + своя инфраструктура (домен/ICMP) | есть (старая схема `xdns`) | есть | отложено |
| `realm` (UDP hole punching) | UDP | да + точка встречи | **нет** (29.05.2026) | есть | отложено |
| `quicParams` | QUIC | — | есть | есть | параметры hysteria/XHTTP/3 |

Версии — по датам слияния из сравнения `v26.3.27...v26.9.9` [релиз].

**Что это значит для нас.**

- **Сквозная передача уже работает.** Outbound панели (VLESS и прочие через Xray) идёт в ядро целиком,
  вместе с `finalmask` [код: `_fromPanel`]. Клиенту делать нечего — пока ядро маску знает.
- **⚠️ Не знает — отказ всего конфига.** Неизвестный тип маски роняет сборку конфига [check]. Для
  профиля «Авто» (балансировщик на десятки outbound) одна маска `xmc`/`realm` в одном узле = весь профиль
  не поднимается на Windows. Неизвестное *поле* же, наоборот, молча игнорируется. Оба исхода плохие.
- **Схема подвижна:** `udpHop` переехал из `hysteriaSettings` в `finalmask.quicParams` (26.3.27), а в
  26.9.8 — в отдельную UDP-маску (#6327); у `xdns` `domain` удалён в пользу `resolvers`/`domains` (#5872).
- **Рекомендация:** сами маски, кроме `fragment`, — **нужна нода, отложено**. Предпосылка — **выровнять
  Windows-Xray с Android** (§3.9): иначе панель, включив новую маску, отрежет Windows-клиентов.

### 3.3 Фрагментация и noises в Xray — что у нас уже есть

**Есть:** `tlshello`-фрагментация через `freedom`-outbound и `dialerProxy` — только в «Автонастройке» и
при закреплённой вариации. `deepVariants` перебирает 7 отпечатков × с/без фрагментации
(`auto_config_engine.dart:538-551`) [код].

**noises** (`freedom.settings.noises`, UDP) не используем и не нужно: они для UDP-протоколов, которых у
нас через Xray нет. Старая форма `noise = {…}` в текущем ядре — ошибка «removed feature» [код:
`infra/conf/freedom.go:146`].

**finalmask `fragment`** делает то же без второго outbound'а, плюс `lengths`/`delays` по сегментам (с
22.06.2026, #6334 — у Windows 26.3.27 нет). В 26.9.8 изменилось поведение `freedom` при `dialerProxy`
(«Skip domain resolution and `finalRules` when using `sockopt.dialerProxy`», #6742) — при обновлении
Windows-ядра нашу схему фрагментации проверять заново.

**Риск.** Против нынешней эвристики ТСПУ (§3.5) фрагментация, по отзывам, не помогает: «ничего не
помогало — фрагментация, mux, смена sni, даже хоста» [сообщество: #6293]. Поверх REALITY добавляет
отличимость (`rejected-approaches`).

**Рекомендация:** оставить как есть. Перенос на `finalmask.tcp` — необязательная чистка, делать вместе с
обновлением Windows-Xray, не отдельно. Кандидат на автоматический запасной путь (`QUIC_V2.md` §5) —
только после живых данных.

### 3.4 `tls_fragment` / `tls_record_fragment` в sing-box — для трафика «Прямо»

**Что это.** Поле действия `route` [док, код: `option/rule_action.go:168-170`]:
`tls_fragment` — режет ClientHello на TCP-сегменты и ждёт подтверждения (на Windows время ожидания
определяется автоматически **только с правами администратора** — TUN-процесс у нас их имеет);
`tls_record_fragment` — режет на несколько TLS-записей. Взаимоисключающие [код: `rule_action.go:184`].
То же есть полями `fragment`/`record_fragment` у TLS outbound'а. Сама документация оговаривает: «intended
to circumvent simple firewalls based on plaintext packet matching, and should not be used to circumvent
real censorship» [док].

**Сервер.** Не нужен. Это замена внешнего zapret/byedpi для сайтов, которые человек пустил «Прямо»,
а ТСПУ их замедляет (`BACKLOG` уже отмечал: апгрейд до 1.13 «закрывает пункт byedpi без третьего бинаря»).

**Клиент / ядра.**

| Платформа | Режим | Можно сейчас? |
|---|---|---|
| Android | весь «Прямо» идёт через sing-box 1.13.14 | **да** [код] |
| Windows | TUN, sing-box 1.11.15 | **нет** — `unknown field "tls_fragment"` [check] |
| Windows | системный прокси, «Прямо» через Xray `freedom` | технически да: `freedom.fragment` в 26.3.27 принят [check] — но это вторая реализация той же функции |

**Трудоёмкость.** Android: флаг на правиле сайта («Прямо + фрагментировать»), строитель, тест, прогон в
эмуляторе — день. Эффект против ТСПУ в эмуляторе не проверить (он ходит через хост): только живьём у
владельца в России. Windows — после перехода на sing-box 1.13 (BACKLOG, пункт 3).

**Риск.** Задержка первого соединения (запасное ожидание 500 мс, где его не определить), редкие поломки
сайтов со странными TLS-стеками. Включать **только по правилу сайта**, не глобально: под глобальной
фрагментацией окажутся и банки, и госуслуги. Подавать как «чтобы работал сайт», не как «скрытность».

**Рекомендация.** Android — **встроить сейчас** как опцию правила, выключено по умолчанию. Windows —
**после перехода на sing-box 1.13**; ветку через `freedom` отдельно не строить, чтобы не развести платформы.

### 3.5 Отпечаток uTLS

**Факты о нас** [код]:
- из XRAY_JSON `fingerprint` идёт как есть — эксперимент панели 23.09 (разные отпечатки по нодам) чистый;
- запасной `chrome` — только у REALITY-ссылки без `fp` (`xray_outbound_factory.dart:193`);
- «Автонастройка»: по умолчанию `fingerprints = ['chrome']` (`app_settings.dart:904`), глубокий перебор —
  `chrome, firefox, safari, edge, ios, android, randomized` (`auto_config_engine.dart:540`);
- **у hysteria2 отпечаток не применяется и применить нельзя:** QUIC в sing-box требует стандартный
  `crypto/tls`, uTLS-конфиг отвечает `unsupported usage for uTLS` [код:
  `common/tls/utls_client.go:56`, `sing-quic/quic.go:44`]. Наш строитель hy2 `utls` и не пишет — верно.
  Заметим: `sing-box check` hy2 с `utls` **принимает** [check], ошибка была бы только при соединении.
  JA4 у hysteria2 — всегда отпечаток Go.

**Что известно о блокировках** [сообщество]:
- статья на Хабре (пересказ в Xray-core #6293, июнь 2026): ТСПУ смотрит на подсеть адреса, SNI и
  отпечаток; «подозрительные» — Chrome, Safari, iOS; у большинства операторов проходят Firefox, Android,
  OkHttp, Edge, 360, QQ. **Больше трёх одновременных TLS-рукопожатий к одному SNI за 60 с (с интервалом
  меньше ~20–50 мс) — все TLS-соединения «замораживаются» на 120 с; смена отпечатка после этого — на
  600 с, при любом SNI**;
- RPRX там же (#6299): отпечаток Chrome в Xray актуален, Россия ограничивает число соединений, «включите
  любой mux»;
- v2rayNG #5406: сочетание «SNI Google + chrome» даёт сброс, `ios`/`qq` восстанавливают; `firefox` в
  одной бета-сборке тоже ловился;
- Xray #6714 (закрыт 03.09.2026): **`randomized` объявляет `X25519MLKEM768` без ключа к нему, uTLS
  обрывает рукопожатие после законного HelloRetryRequest — сервер недоступен до перезапуска процесса**.

Сверка с картой панели: на части нод стоят `safari` и `ios`, которые статья относит к подозрительным.
Для чистоты их опыта это нормально, но стоит им сказать.

**Сервер.** Не нужен: сервер отпечаток не проверяет (слова агента панели).

**Рекомендация — встроить сейчас:**
1. убрать `randomized` из `deepVariants` (баг ядра, а не «ещё один вариант»);
2. дефолт автонастройки `['chrome']` → например `['firefox', 'qq']`, и запасной `fp` у REALITY-ссылки
   без `fp` — **спросить владельца**, а не выбирать молча (память `ask-before-guessing`);
3. в «Автонастройке» не менять отпечаток на одном сервере чаще раза в несколько минут (§3.6) — иначе
   перебор отпечатков сам воспроизводит сценарий «600 с».

### 3.6 Темп рукопожатий: mux и наши собственные всплески

Если эвристика из §3.5 верна, решает не «какой» ClientHello, а **сколько их и как часто**.

**mux.** С `flow: xtls-rprx-vision` Mux не годится: сервер рвёт Mux-соединения с TCP-запросами
[код: `proxy/vless/outbound/outbound.go:263`, «let server break Mux connections that contain TCP
requests»]. У XHTTP есть `xmux` — пул переиспользуемых соединений, настройка клиентская. Какие хосты
панели на XHTTP — не проверял; по VLESS+Vision без mux каждое TCP-соединение браузера = отдельное
TLS-рукопожатие к ноде, и это клиент не исправит — это выбор транспорта на панели.

**Наши собственные всплески** — это уже зона клиента [код, число соединений — оценка]:
- пинг, фаза 2 (GET/HEAD через харнесс) — параллельно по всем «ответившим» серверам;
- проверка сервисов при подъёме туннеля — до 14 запросов почти одновременно через ОДНУ ноду, то есть до
  14 рукопожатий к одному SNI за секунды;
- «Автонастройка» — серия подключений к одному серверу с разными отпечатками.

Гипотеза, которую стоит проверить живьём: часть жалоб «подключилось и через минуту всё встало» —
это наш же автопрогон сервисов, сработавший триггером «заморозки».

**Трудоёмкость.** Ограничить параллельность собственных проб к одной ноде (2–3) с разносом по времени —
часы на каждую подсистему плюс тесты. Живая проверка эффекта — только из России.

**Риск.** Пинг и проверка сервисов станут медленнее. Выигрыш не доказан.

**Рекомендация: встроить сейчас** ограничение параллельности наших проб к одному серверу; про XHTTP/`xmux`
спросить панель.

### 3.7 Port knocking / SPA (fwknop)

**Что это.** Порт в DROP; клиент шлёт один подписанный UDP-пакет (по умолчанию порт 62201, Rijndael или
GPG + HMAC-SHA-256, 16 байт случайных данных и защита от повтора по дайджесту), демон открывает порт
адресу из пакета на `FW_ACCESS_TIMEOUT` (в примере 30 с); уже установленные соединения держит conntrack
после снятия правила. За NAT: `-R` узнаёт внешний адрес через HTTPS, `-a` задаёт его явно [док: fwknop].

**Сервер.** Демон `fwknopd` (libpcap + iptables/firewalld) и правило DROP на **каждой** ноде — нода.

**Клиент.** Свой построитель SPA-пакета на Dart (AES + HMAC в формате fwknop) — посильно. Но стучать
надо перед каждым подключением, каждым переподключением, после смены сети и — при Vision без mux — перед
каждым новым TCP-соединением после истечения окна (значит, окно = вся сессия, и смысл «на несколько
секунд» пропадает). На мобильном CGNAT внешний адрес SPA-пакета и TCP-соединения может различаться
(пул адресов) — не проверено.

**Риск.** Стоковые клиенты стучать не умеют (агент панели сам это пишет) → нужен отдельный вход только
для нашего приложения. Одиночный случайный UDP-пакет перед каждым соединением — сам по себе признак.
Закрытый 443 у адреса, который должен выглядеть сайтом, спорит с легендой REALITY: её смысл —
открытый порт, отвечающий как донор.

**Рекомендация: не делать сейчас.** Активные пробы TCP уже закрывает REALITY, UDP — salamander, без
демона. Возвращаться, только если панель решит прятать входы без REALITY; тогда оценка клиента — 2–3 дня
плюс демон на нодах.

### 3.8 QUIC v2

Разобран в `QUIC_V2.md`. Добавление: **salamander и QUIC v2 закрывают одну и ту же дыру** (SNI в Initial)
разной ценой — v2 требует патча ядра на клиенте и ничего на сервере, salamander — ничего в ядре и
настройки сервера. Для входящего с salamander v2 не нужен.
