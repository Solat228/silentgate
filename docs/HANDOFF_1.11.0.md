## 3. Как собирать

⚠️ **С диска `I:` НЕ ЗАПУСКАЕТСЯ НИ ОДИН СКРИПТ.** На машине включён AppLocker, для коллекции
Script разрешены только `%PROGRAMFILES%`, `%WINDIR%` и `%OSDRIVE%` (то есть `C:`). Junction не
спасает — Windows разрешает его в настоящий путь и блокирует. Поэтому:

- **Двойным кликом** — ярлыки `Собрать APK.lnk` / `Собрать Windows.lnk` в корне (цель — `cmd.exe`
  на `C:`, копируют батник в `%TEMP%` и запускают оттуда; источник батника один).
- **Windows вручную:** `cd C:\dev\silentgate\app && flutter build windows`, затем этап упаковки
  из `build-exe.bat` — копирование ядер, гео-баз и лицензий.
- **Android:** `build-apk.bat` зеркалит `app\` в `C:\dev\silentgate-apk` и собирает из
  `C:\dev\silentgate-apk\app`. ⚠️ **Обязателен `--split-per-abi`**: `cores.aar` несёт ядра под обе
  ABI, и без флага APK весит 135 МБ вместо 76 МБ. `--target-platform` здесь не помогает — он
  фильтрует только библиотеки самого Flutter, а не `jniLibs` из AAR.

Проверка без подключения:

```
cd C:\dev\silentgate\app
flutter analyze
flutter test
```

Батники править **только в кодировке OEM (cp866) и с CRLF** — `cmd` перечитывает `.bat` по
байтовым смещениям и на UTF-8 сбивается, продолжая исполнение с середины строки.

При `LNK1104` на линковке — exe занят запущенным приложением. Закрывать процесс, **а не
переименовывать файл**: переименованные копии копятся в релизной папке мусором.

## 4. Чего нельзя трогать

1. **⚠️ НЕ ВКЛЮЧАТЬ VPN НА ХОСТЕ.** Никаких `connect`, установки системного прокси и проб через
   реальные серверы на боевой машине. Запустить приложение, чтобы убедиться, что оно стартует, —
   можно; нажимать Connect — нельзя. **Исключение:** внутри изолированной Hyper-V VM `SG-Test` и
   эмулятора `sg-test` включать МОЖНО и НУЖНО.
2. **Не убивать процессы владельца** — ни `xray`, ни Happ, ни другие клиенты: он никогда не
   запускает их одновременно с нашим.
3. **Не писать на рабочий стол** и не плодить копии сборок.
4. **Тесты не должны трогать боевой `%APPDATA%`** — предохранитель стоит в `AppPaths`, обходить
   его нельзя. Один тест уже переписал владельцу `subscriptions.json` с четырьмя реальными
   подписками на выдуманную.
5. **Не возвращать удалённое осознанно:** страницу-заглушку при блокировке; `Get-NetAdapter` в
   путь проверки помех (не возвращается вовсе, заменён на `NetworkInterface.list()`); исключение
   адаптера по ИМЕНИ в `NetworkWatcher` (давало вечный цикл переподключений).
6. **Не писать настоящие адреса** — ни IP владельца, ни его серверов: в текстах звёздочки,
   в тестах TEST-NET.
7. **Ворктри `wfp-selected-process-names` не сносить** — в нём сборки (§2).

## 6. Вопросы, закрытые ОТРИЦАТЕЛЬНО — не поднимать снова

| Вопрос | Ответ и почему |
|---|---|
| Увод приложения мимо туннеля по имени на Windows | `exclude_process_name` в sing-box **не существует**; `exclude_package` ядро принимает с кодом 0 и молча не применяет. Взамен — деление по подсетям (`tunRouteOnlyCidrs`). ⚠️ Маршрутные правила по `process_name` и блокировка по программам фильтрами WFP при этом работают — это три разные вещи, не путать. |
| Свой callout-драйвер режима ядра | Решение владельца 04.08.2026: **не делаем**. ⚠️ Причина не «невозможно»: `FwpmConnectionPolicyAdd0` — живая юзермодная функция, сторонний `.sys` не нужен. Причина — необкатанный кандидат, админ на каждую правку и DNS этим всё равно не закрывается. |
| Страница-заглушка при блокировке | Удалена. Подменить https без своего корневого CA невозможно, ставить CA нельзя — он даёт читать весь TLS пользователя. Работала только на голом HTTP, то есть почти нигде. |
| Скрыть факт VPN на Android | Нельзя: `NetworkCapabilities.TRANSPORT_VPN` отдаётся без разрешений, сокрытие требует root и модуля ядра. **Не обещать «невидимость VPN» в интерфейсе.** |
| Сменить формат установщика (MSI/MSIX) | MSI старше (1999); MSIX недоступен по существу — контейнер не даёт ни wintun, ни правки WinINET, ни двух процессов ядер, и обязателен к подписи. Предупреждение SmartScreen идёт от отсутствия подписи, а не от технологии. |
| `CloseApplications` (Restart Manager) для обновления поверх запущенного | **Не помогает, проверено.** Он шлёт `WM_CLOSE`, а у нас на закрытие окна висит сворачивание в трей: процесс жив, файл занят, RM рапортует об успехе. | Правила «DNS этого приложения» на Windows | Не работают: DNS-запрос принадлежит `svchost.exe`, ядро само это пишет в лог. На Android — штатно. |
| Xray-native TUN как замена sing-box | Снят: sing-box в поставке и так, второе ядро под ту же задачу не нужно. |
| Маршрутизация по приложениям на iOS | Упирается в отсутствующий API, а не в объём работ. Не обещать. |

## 7. Грабли — классы ошибок, а не отдельные баги

- **«Ядро приняло конфиг» ≠ «правило работает».** `sing-box check` возвращает 0 на правиле,
  ссылающемся на несуществующий тег outbound, и на полях, которых на этой платформе нет вовсе.
- **«Строка есть в бинарнике» ≠ «приложение запускается».** 15.08.2026 так «проверили» APK 1.4.3,
  который падал в цикл раз в секунду с заблокированным трафиком.
- **«Зелёные тесты» ≠ «работает».** 1412 тестов были зелёными на той же сборке: беда рождалась
  на стыке двух мест, каждое из которых по отдельности выглядит разумным.
- **Поле пишется, но не читается.** `toJson`/`fromJson` независимы, компилятор такое не ловит.
  Страж — `test/settings_roundtrip_test.dart`, перебирает ВСЕ ключи, а не список руками.
- **Два разбора одной строки — всегда дыра.** Разрешение и исполнение обязаны спрашивать один и
  тот же код: `needsToken` со своим разбором пропускал без токена то, что исполнитель прекрасно
  распознавал и выполнял.
- **Комментарий, утверждающий невозможность, — укрытие для дефекта.** Порт харнесса на Android
  слушал без пароля два релиза, потому что комментарии говорили «на Android харнесса нет вовсе».
  Никто не искал того, чего по описанию не существует.
- **Гейт по факту, а не по косвенному признаку.** «Есть креды» и «поднят SOCKS» — разные
  утверждения; запасной DNS поднимался по первому, и весь DNS уходил провайдеру.
- **Невидимый байт в исходнике.** Управляющие символы задавать кодом (`String.fromCharCode(0x1b)`),
  а не самим байтом: пропавший ESC снимал цвет наполовину, глазами такое не увидеть.
- **Связка провайдеров ради побочного эффекта требует `lazy: false`.** Без него `update()` не
  зовётся никогда: локальный API не работал ни разу ни при каких настройках.
- **После агентов — всегда `git status`.** За ними уже оставался мусор в `test/`.
- **Дата файла ничего не доказывает.** Dart-код Windows живёт в `data\app.so`, а не в
  `silentgate.exe`; APK мог собраться из второй копии проекта без последних правок.

## 8. Как проверять

**Windows — Hyper-V VM `SG-Test`** (клон, учётка `sgtest`, управление через PowerShell Direct).
**Android — эмулятор `sg-test`** (AVD есть, SDK `C:\dev\android\sdk`). Оба обязательны, не
«по возможности». Внутри них VPN включать можно и нужно.

Минимальный прогон на эмуляторе:

```
C:\dev\android\sdk\emulator\emulator.exe -avd sg-test -no-snapshot-load
C:\dev\android\sdk\platform-tools\adb.exe install -r <apk>
adb shell am start -n lol.silentgate/.MainActivity
adb logcat -c && adb logcat -s flutter:* AndroidRuntime:E lol.silentgate:*
adb shell am start -a android.intent.action.VIEW -d "silentgate://connect"
```

Проверять не «туннель поднялся», а «туннель ЖИВЁТ дольше минуты».

⚠️ **ГАСИТЬ СТЕНД ЗА СОБОЙ** — требование владельца: `adb emu kill` и
`Stop-VM -Name SG-Test -Force`. На машине владельца в это время идёт его работа.

⚠️ **Ловушки стенда:** эмулятор ходит через хост — если на хосте поднят чужой VPN, выходной IP
ничего не доказывает. VM переведена на внешний коммутатор `SG-External`: Default Switch давал
ложные «нет интернета». Мишени брать живые и смотреть по каждой отдельно, а не суммой.
Жёсткий сброс VM (`Restart-VM -Force`) теряет только что записанные файлы — сверять содержимое
до перезагрузки.
