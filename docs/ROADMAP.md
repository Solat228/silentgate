## M0 — Каркас и движок (Windows) ✅

**Цель:** проект собирается на Windows, ядро Xray запускается и проксирует.

- [x] Выбор стека, структура репозитория, документация.
- [x] Установка Flutter SDK, `flutter create` для Windows.
- [ ] `tools/fetch-xray.ps1` — загрузка `xray.exe` (Windows) в `engine/windows/bin/`.
- [ ] `core/xray/xray_config_builder.dart` — генерация Xray-JSON (inbound SOCKS+HTTP, один outbound).
- [ ] `engine/windows/windows_proxy_engine.dart` — запуск/остановка `xray.exe` как дочернего процесса.
- [ ] Ручная проверка: hardcoded `vless://` → конфиг → `xray.exe` → трафик через SOCKS 127.0.0.1:10808.

**Готово, когда:** `flutter run -d windows` открывает окно; при нажатии «Connect» на зашитом сервере
запускается `xray.exe`, и `curl -x socks5://127.0.0.1:10808 https://ifconfig.me` отдаёт IP сервера.

## M1 — MVP «Подключалка» (Windows) ✅

**Цель:** минимальный рабочий клиент, которым можно пользоваться.

**Фичи:**
- [ ] Экран импорта: вставить sub URL или deep link (`silentgate://…`), либо `vless://`-ссылку.
- [ ] Загрузка подписки: HTTP GET → base64-decode → список серверов (парсер `vless/vmess/trojan/ss`).
- [ ] Экран «Домой»: большая кнопка Connect/Disconnect, текущий статус, выбранный сервер.
- [ ] Список серверов: выбрать активный.
- [ ] Подключение: генерация конфига активного сервера → `xray.exe` → **установка системного прокси**
      (реестр WinINET) → трафик всех приложений идёт через VPN.
- [ ] Отключение: остановка ядра + снятие системного прокси (гарантированно, в т.ч. при краше).
- [ ] Хранение: sub URL + выбранный сервер сохраняются между запусками (`flutter_secure_storage`).
- [ ] Индикатор трафика (вверх/вниз) через gRPC StatsService ядра.

**Критерии готовности:** пользователь вставляет реальную ссылку Remnawave → видит серверы → жмёт Connect →
весь трафик Windows идёт через VPN → Disconnect всё чисто снимает. Настройки переживают перезапуск.

Детали реализации — [platforms/WINDOWS.md](platforms/WINDOWS.md).

## M5 — TUN-режим / полный туннель (Windows) ✅ (живой тест пройден в 0.13.1)

**Цель:** захват всего трафика без системного прокси (ловит UDP и приложения, игнорящие прокси).

- [x] **sing-box** отдельным процессом как TUN-роутер (wintun) + маршрутизация; прокси-трафик → Xray (Reality).
- [x] **Раздельное туннелирование**: по приложениям (выбор из запущенных процессов / .exe) и по доменам.
- [x] **UAC по требованию** через `ShellExecuteEx("runas")`; остановка привилегированного процесса через stop-файл.
- [x] Loop-avoidance (процессы ядра и приватные адреса — direct); переключатель «Системный прокси / TUN».
- [ ] Живой тест на реальном подключении (UAC, wintun, split) — за пользователем.
- [ ] Опционально: прототип Xray-native TUN+process (MPL, одна программа) как альтернатива sing-box.

> Решено: sing-box (GPL) допустим отдельным процессом («mere aggregation»). Xray с v26.1.23 тоже умеет TUN+process —
> кандидат на упрощение, требует проверки на живом TUN.

## M7 — Android 🟢

**Цель:** Android-клиент с **паритетом 1-в-1** по функциям и визуальному языку с Windows 1.0.0,
при мобильной вёрстке. Общий Dart-код — тот же самый, без второй копии логики.

Полный план (77 задач по 9 фазам), план будущих апдейтов и 57 подводных камней —
**[platforms/ANDROID.md](platforms/ANDROID.md)**; обоснование архитектурных решений —
[platforms/ANDROID_DESIGN.md](platforms/ANDROID_DESIGN.md).

Ключевые решения (детали — в тех документах):

- **Форк = ветка `android` в этом же репозитории,** один Flutter-пакет. Отдельная копия отвергнута:
  ~85 % кода общего, две копии убивают паритет на первом же багфиксе.
- **Порт — это вычленение платформенного слоя,** а не второе приложение: ~70 % кода едет как есть,
  заменяются четыре абстракции (движок, TUN, харнесс проб, каталог приложений).
- **Датапуть TUN:** `VpnService` отдаёт fd ядру через колбэк `OpenTun`, sing-box (`libbox`) делает
  TUN + маршрутизацию + DNS + per-app правила и форвардит в локальный SOCKS 10808, где Xray
  (`libXray`) поднимает VLESS/Reality и панельные профили «Авто». **Архитектура идентична Windows**,
  поэтому ~85 % генератора `singbox_config_builder.dart` переиспользуется.
- **Движок живёт в foreground-сервисе,** а не в процессе UI — единственное принципиальное
  расхождение с Windows.
- **Блокировка приложений работает** (`package_name` + `action: reject`), но требует Android 10+;
  на старых версиях — явная пометка в UI. Молча превращать «блок» в «разрешено» запрещено.
- **Лицензия — GPL-3.0** (файл `LICENSE`, README, CHANGELOG 1.0.0). Это и открыло путь к `libbox`:
  линковка sing-box законна. Прежний «блокер-противоречие» снят, `CLAUDE.md` и `STACK_DECISION.md`
  поправлены 27.07.2026.

## M8 — iOS 🔒

**Цель:** iOS-версия. Самый сложный этап; заранее учесть ограничения.

- [ ] Аккаунт Apple Developer типа **Organization** (нужно юрлицо) — App Store Guideline 5.4.
- [ ] Нативный Swift `NEPacketTunnelProvider` (extension) — Dart в extension не работает.
- [ ] `libXray.xcframework` (gomobile/cgo) линкуется в extension; TUN через `xray.tun.fd` или hev-socks5-tunnel.
- [ ] Управление через `NETunnelProviderManager` + App Group (по образцу Hiddify).
- [ ] **Лимит памяти NE ~50 МБ:** обрезка geo-файлов, GC libXray раз/сек, `GOMEMLIMIT`, отключение статистики.
      Проверять на реальных устройствах рано.
- [ ] Риски RU App Store (удаления по требованию RKN) → нейтральное имя, TestFlight, инструкция non-RU Apple ID.
- [ ] Коммерция вне приложения (бот/сайт), без ссылок на покупку из iOS-сборки (иначе — Apple IAP).

- [ ] ⚠️ **Раздельного туннелирования ПО ПРИЛОЖЕНИЯМ на iOS нет** — упирается в отсутствующий API,
      а не в объём работы. Экран «по приложениям» скрывать целиком, правила по сайтам/IP/гео остаются.
- [ ] ⚠️ Решить судьбу **sing-box**: GPL-3.0 конфликтует с условиями App Store, исключение по §7 они
      добавлять отказались. Xray (MPL) безопасен; без sing-box под вопросом hysteria2 и TUN-слой.

Детали и риски — [platforms/IOS.md](platforms/IOS.md).
