# Подпись кода (SmartScreen / антивирусы)

Неподписанный `silentgate.exe` и установщик вызывают предупреждение **SmartScreen**
(«Неизвестный издатель») и повышают шанс ложных срабатываний антивирусов. Для
коммерческого релиза приложение и установщик стоит подписывать.

## Что нужно
- **Сертификат Authenticode** (OV или, лучше, **EV** — EV сразу снимает SmartScreen-репутацию).
  Поставщики: DigiCert, Sectigo, GlobalSign и т.п. EV обычно на аппаратном токене/HSM.
- **signtool** из Windows SDK (в PATH).

## Подпись exe (в сборке)
`build-exe.bat` подписывает `silentgate.exe` автоматически, ЕСЛИ задан сертификат
(иначе шаг пропускается — сборка не ломается):

```bat
:: из PFX-файла:
set "SIGN_PFX=C:\path\cert.pfx"
set "SIGN_PASS=пароль"
build-exe.bat

:: ИЛИ из системного хранилища (напр. EV-токен) по отпечатку:
set "SIGN_THUMBPRINT=aa11bb22cc33..."
build-exe.bat
```

Используется SHA-256 + RFC 3161 timestamp (`timestamp.digicert.com`) — подпись
остаётся валидной после истечения сертификата.

## Подпись установщика (Inno Setup, `installer/silentgate.iss`)
Inno Setup умеет подписывать выходной setup через директиву `SignTool`:

1. В Inno Setup IDE: **Tools → Configure Sign Tools…** добавить инструмент, напр. `sign`:
   `signtool.exe sign /fd SHA256 /f "C:\path\cert.pfx" /p $q$p$q /tr http://timestamp.digicert.com /td SHA256 $f`
2. В `[Setup]` добавить:
   ```
   SignTool=sign
   SignedUninstaller=yes
   ```

После этого и `setup.exe`, и распакованный `silentgate.exe` (если подписан на шаге
сборки) будут доверенными.

## Проверка
```
signtool verify /pa /v "build\windows\x64\runner\Release\silentgate.exe"
```

> Примечание: сам сертификат в репозиторий НЕ кладём; путь/пароль — через переменные
> окружения на машине сборки или CI-секреты.

## Подпись манифеста обновлений (1.14.0) — это другое

С 1.14.0 приложение обновляется само и проверяет скачанное по **подписи манифеста релиза**.
С Authenticode её легко спутать, но это две независимые вещи с разными задачами:

| | Authenticode (этот документ выше) | Подпись манифеста обновлений |
|---|---|---|
| Что подписано | сам `silentgate.exe` / установщик | `SilentGate-<версия>.manifest.json` — список активов релиза с размерами и SHA-256 |
| Кто проверяет | Windows: SmartScreen, UAC, антивирусы | само приложение перед установкой обновления |
| Чем | сертификат от центра сертификации (платный, OV/EV) | свой ключ Ed25519, публичная половина зашита в приложение |
| Платформы | только Windows | Windows и Android |
| Что даёт | репутацию издателя: меньше предупреждений и ложных срабатываний | гарантию, что обновление выпустил владелец, а не тот, кто подменил файл на сервере или по дороге |
| Есть ли сейчас | нет (сертификата нет, шаг сборки пропускается) | да, обязательна для самообновления |

**Зачем обе.** Authenticode говорит Windows «этот издатель известен», но приложение им не
пользуется и без него обходится: самообновление запускает установщик без Mark-of-the-Web, и
SmartScreen тут не участвует (разбор — `docs/APP_UPDATE.md`, «Почему SmartScreen не мешает»).
Подпись манифеста говорит приложению «этот файл — от нас»; без неё самообновление было бы
способом доставить на машину пользователя чужой exe, подменив один ответ сервера. Появится
сертификат Authenticode — подпись манифеста останется: она покрывает и APK, и случай, когда
сертификат есть у кого-то ещё.

**Ключ.**
- Приватный — `signing/update_ed25519.key`: 32-байтный seed в base64, одна строка. Каталог
  `signing/` в `.gitignore` (там же лежит keystore Android). Создаётся один раз
  `cd app && dart run tool/update_keygen.dart`, который пишет и ключ, и публичную половину в
  `app/lib/core/update/update_pubkey.dart` (`kUpdatePublicKeyBase64`). Существующий ключ без
  `--force` не перезаписывается — и `--force` не звать, см. ниже.
- Публичный зашит в приложение и **не переопределяется ничем** — ни переменной окружения, ни
  настройками, ни тестовым override адреса обновлений.
- Подписывает `cd app && dart run tool/sign_release.dart <версия> <stable|beta> <файлы…>` —
  процедура выпуска в `docs/APP_UPDATE_SERVER.md` §3a.

⚠️ **Потеря приватного ключа = выпущенные сборки больше не примут ни одного обновления.**
Новый ключ можно зашить только в новую сборку, а поставить её уже установленные копии смогут
лишь руками, по ссылке. Держать резервную копию ключа там же, где резервную копию keystore
Android, — вне репозитория и вне этой машины.

⚠️ **Утечка приватного ключа = любой, у кого он есть, может выпустить «обновление».** Ключ не
кладётся ни на сервер обновлений, ни в CI, ни в журнал; сайту он не нужен вовсе — сайт
раздаёт уже подписанные файлы.
