# Сервер обновлений SilentGate — техническое задание

**Кому:** тому, кто делает серверную часть на `silentgate.lol`.
**Автор:** команда клиента. **Дата:** 15.08.2026. **Версия клиента:** 1.5.1.

Документ описывает **один HTTP-эндпоинт** и то, что за ним должно стоять. Клиент уже написан
и ждёт этот эндпоинт — менять клиент под другой формат не нужно и не следует.

---

## 1. Зачем это вообще

Клиент проверяет, не вышла ли новая версия себя. Источников **два**:

| | Источник | Роль |
|---|---|---|
| 1 | GitHub Releases (`api.github.com`) | основной |
| 2 | **`silentgate.lol` — предмет этого документа** | запасной |

⚠️ **Запасной здесь не формальность, а необходимость.** 15.08.2026 выяснилось, что у владельца
`api.github.com` **не открывается вовсе**: TLS-рукопожатие падает с
`CERTIFICATE_VERIFY_FAILED: Hostname mismatch`. Воспроизведено в чистой виртуальной машине, где
VPN не поднимался ни разу, при полностью живом `github.com` — то есть API перехватывают на
стороне провайдера. Клиентом пользуются ровно там, где интернет фильтруют, поэтому «основной
источник недоступен» для нас **обычное состояние, а не авария**.

Клиент спрашивает GitHub, и **при любом его отказе** идёт на наш сайт. Пока GitHub отвечает,
сайт не запрашивается вовсе.

---

## 2. Контракт эндпоинта

### Запрос

```
GET https://silentgate.lol/api/app-version
User-Agent: SilentGate/<версия> (Windows|Android)
```

**Один путь на обе платформы.** Раньше их было два (`app-version` и `app-version-android`), и
андроидный так и не создали — из-за чего телефон **молча не находил обновлений вообще**. Не
повторять: платформу, если она нужна, определять по `User-Agent`, а не по пути.

Аутентификации нет. Cookie нет. Тела нет.

### Ответ — 200 и JSON

```json
{
  "version": "1.5.1",
  "url": "https://silentgate.lol/download/SilentGateSetup-1.5.1.exe",
  "notes": "Что нового в этой версии, коротко и по-человечески",
  "page": "https://silentgate.lol/download"
}
```

| Поле | Обяз. | Что это |
|---|---|---|
| `version` | **да** | Версия вида `1.5.1`. Приставка `v` допускается — клиент её срежет. Пустая строка = ответ считается непонятным. |
| `url` | нет | Прямая ссылка на файл **для платформы запрашивающего**. ⚠️ Только `https` — по `http` клиент ссылку отбросит и покажет страницу вместо неё. |
| `notes` | нет | Текст «что нового». Показывается пользователю целиком. |
| `page` | нет | Страница загрузок. Открывается, когда `url` нет. По умолчанию `https://silentgate.lol/download`. |

Лишние поля игнорируются — добавлять можно, ломать формат нельзя.

### Как клиент это трактует

- `version` **новее** установленной → пользователю показывается уведомление с кнопкой.
- `version` равна или старее → «у вас последняя версия».
- Не 200, не JSON, нет `version` → **«проверить не удалось»**, с причиной.

⚠️ **Три исхода, а не два.** «Не смогли проверить» — это отдельный ответ, а не «обновлений нет».
Раньше клиент их путал и говорил «у вас последняя версия» человеку без сети; так делать нельзя
и на сервере: **не отдавайте 200 с текущей версией, когда на самом деле не знаете ответа.**
Лучше честный 503.

### Коды ошибок

| Код | Когда | Что делает клиент |
|---|---|---|
| `200` | есть ответ | разбирает |
| `404` | эндпоинта нет | считает проверку неудавшейся |
| `429` | слишком часто | то же; см. §4 про частоту |
| `5xx` | у нас беда | то же |

Отдавать `204` или пустое тело **не надо**: клиент воспримет это как «сервер ответил непонятным
образом», и это будет правдой.

## 3. Платформы и файлы

Клиент собирается под три артефакта:

| Платформа | Файл | Признак |
|---|---|---|
| Windows | `SilentGateSetup-<версия>.exe` | установщик Inno Setup |
| Android, телефон | `SilentGate-<версия>-arm64-v8a.apk` | **это нужно людям** |
| Android, эмулятор | `SilentGate-<версия>-x86_64.apk` | для разработки |

⚠️ **Никогда не отдавайте телефону `x86_64`.** Оба файла содержат `.apk`, и подмена приведёт к
установке сборки, которая на телефоне не запустится. Если платформа не определилась — не
отдавайте `url` совсем, отдайте `page`: пусть человек выберет сам.

⚠️ **Никогда не отдавайте Android ссылку на `.exe`.** Это уже случалось, когда путь был общим.

Файлы обязаны лежать на `https` и отдаваться с `Content-Length` — без него клиент не покажет
размер загрузки.

## 4. Нагрузка, кэш, частота

- Клиент спрашивает **один раз при запуске** (если проверка включена в настройках) и по нажатию
  кнопки в настройках.
- Ответ маленький и одинаковый для всех — **кэшируйте**. `Cache-Control: public, max-age=300`
  разумно: пять минут задержки в доставке новости о версии никому не мешают, а всплеск после
  релиза сглаживают.
- Ограничение частоты по адресу допустимо, но **не жёстче 60 запросов в час** — за одним адресом
  сидит и квартира, и офис. При отказе отдавайте `429`, а не `403`: клиент различает их в
  сообщении человеку.

## 5. Чего делать НЕЛЬЗЯ

Это раздел про безопасность и доверие, и он важнее остальных.

1. **Не требовать подписку.** Обновление приложения одинаково для всех — и для тех, у кого
   подписка кончилась. Привязка версии к оплате превратит клиент в заложника биллинга.
2. **Не отдавать разным людям разные версии.** У сервера есть такая возможность (он знает
   пользователя), и именно поэтому он **запасной**, а не основной: чтобы подменить версию,
   пришлось бы подменить оба источника сразу.
3. **Не логировать пользователей.** Запрос анонимный. Не сохраняйте `User-Agent` вместе с
   адресом в долгую таблицу: связка «адрес + версия клиента + время» — это профиль.
   Достаточно счётчиков без персональных данных.
4. **Не отдавать `http`-ссылку на установщик.** Клиент её отбросит, но проблема в самом
   намерении: установщик по открытому каналу можно подменить.
5. **Не ставить редирект на сторонний хостинг файлов** без крайней нужды. Если делаете —
   редирект обязан быть на `https`.

## 6. Сообщения пользователям — отдельная история

Владелец просил описать и это. **Не смешивайте с обновлениями**: `notes` — это «что нового в
версии», а не канал объявлений.

### Что уже есть в клиенте

Панель Remnawave умеет присылать в ответе подписки поля `title` и `announce` — они показываются в
карточке подписки. Это **работающий канал объявлений**, и для «у нас профилактика в субботу» он
подходит лучше нового эндпоинта. Прежде чем строить своё, проверьте, хватает ли его.

### Если всё-таки нужен свой канал

Отдельный эндпоинт, отдельный формат:

```
GET https://silentgate.lol/api/notice
```

```json
{
  "id": "2026-08-maintenance",
  "level": "info",
  "text": "В субботу с 3:00 до 5:00 по МСК возможны перебои.",
  "url": "https://silentgate.lol/blog/maintenance",
  "until": "2026-08-20T02:00:00Z"
}
```

| Поле | Зачем |
|---|---|
| `id` | ⚠️ **Обязательно.** По нему клиент запоминает, что сообщение уже показывал. Без `id` объявление всплывало бы при каждом запуске — так делают приложения, которые перестают читать. |
| `level` | `info` / `warning` / `critical`. Влияет на вид, а не на назойливость. |
| `text` | Текст. Коротко: это всплывающая карточка, а не письмо. |
| `url` | Необязательная ссылка «подробнее». |
| `until` | Когда сообщение протухает. После этой даты клиент его не показывает, даже если сервер продолжает отдавать. |

Пустой ответ (`{}` или 204) означает «объявлений нет» — это нормальный, ожидаемый ответ.

⚠️ **Одно сообщение за раз.** Очередь объявлений на экране — это шум, от которого отмахиваются,
не читая. Если новостей несколько, решайте на сервере, какая важнее.

⚠️ **`critical` — не для маркетинга.** Как только этим уровнем придёт реклама, люди перестанут
читать и настоящие предупреждения. Уровень оправдан для «сервис недоступен» и «смените версию,
в старой дыра».

### Обратная связь ОТ пользователей

Сейчас её нет и по умолчанию **не надо**. Клиент собирает отчёт для поддержки и открывает чат
Telegram — человек отправляет сам, осознанно, видя содержимое файла. Это правильно: в отчёте
техническая информация о его машине.

Если когда-нибудь захотите приём отчётов на сервер — это отдельное решение с явным согласием,
и вот минимальные требования, без которых начинать не стоит:

1. **Только по кнопке пользователя.** Никакой фоновой отправки.
2. **Показать, что именно уходит**, до отправки. Отчёт содержит версии, настройки, журнал.
3. **Срок хранения и удаление по запросу.** Отчёты — это данные человека.
4. **Не принимать то, чего не просили:** ограничение размера, никакого исполняемого содержимого.
5. ⚠️ **Проверить, что в отчёте нет секретов.** Клиент уже маскирует токен подписки, адреса
   серверов и пароли — но это делает *клиент*. Сервер обязан считать входящее недоверенным.

## 7. Как проверить, что сделано верно

```bash
# 1. Отвечает и разбирается
curl -s https://silentgate.lol/api/app-version | jq .

# 2. Версия есть и выглядит версией
curl -s https://silentgate.lol/api/app-version | jq -r .version

# 3. Ссылка на https и файл реально существует
curl -sI "$(curl -s https://silentgate.lol/api/app-version | jq -r .url)" | head -1

# 4. Android получает apk, а не exe
curl -s -A 'SilentGate/1.5.1 (Android)' https://silentgate.lol/api/app-version | jq -r .url
# ожидаем …-arm64-v8a.apk

# 5. Windows получает exe
curl -s -A 'SilentGate/1.5.1 (Windows)' https://silentgate.lol/api/app-version | jq -r .url
# ожидаем …Setup….exe
```

Готово, когда все пять дают ожидаемое, а `curl` без `User-Agent` не роняет сервер.
