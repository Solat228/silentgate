# Сервер обновлений SilentGate — техническое задание

**Кому:** тому, кто делает серверную часть на `silentgate.lol`.
**Автор:** команда клиента. **Дата:** 15.08.2026, дополнено 10.09.2026 (1.13.0, §2b) и
24.09.2026 (1.14.0, самообновление: §2c, §3, §3a, §3b).
**Версия клиента:** 1.5.1 (§1–9), бета-канал — 1.13.0, самообновление — 1.14.0.

Документ описывает **HTTP-эндпоинты** и то, что за ними должно стоять. Клиент уже написан
и ждёт эти эндпоинты — менять клиент под другой формат не нужно и не следует.

⚠️ **§2b — НОВОЕ в 1.13.0.** Повод: 1.12.0 выложена сайтом как GitHub-пререлиз
(`prerelease: true`, `make_latest: false`) + `/opt/updates/beta/`, но клиент до 1.13.0 об
этом канале не знал никак: `/releases/latest` пре-релизы не отдаёт по определению GitHub,
а `/api/app-version` (§2) их тоже никогда не отдавал — и не должен, читайте предупреждение
в §2b про то, почему туда НЕЛЬЗЯ добавлять поле `beta`.

⚠️ **§2c, §3a — НОВОЕ в 1.14.0.** Клиент теперь САМ скачивает и ставит обновление, но только
по **подписанному манифесту релиза** (`SilentGate-<версия>.manifest.json` +
`.manifest.sig`). Релиз без них и ответ сайта без новых полей работают как раньше — кнопкой-
ссылкой; ломать ничего не нужно, но без них самообновления не будет.

---

## 1. Зачем это вообще

Клиент проверяет, не вышла ли новая версия себя. Источников **два**:

| | Источник | Роль |
|---|---|---|
| 1 | GitHub Releases (`api.github.com`) | основной |
| 2 | **`silentgate.lol` — предмет этого документа** | запасной |

⚠️ **Запасной здесь не формальность, а необходимость.** 15.08.2026 выяснилось, что у владельца
`api.github.com` **не открывается вовсе**: TLS-рукопожатие падает с
`CERTIFICATE_VERIFY_FAILED: Hostname mismatch`. Воспроизведено в чистой виртуальной машине, где
VPN не поднимался ни разу, при полностью живом `github.com` — то есть API перехватывают на
стороне провайдера. Клиентом пользуются ровно там, где интернет фильтруют, поэтому «основной
источник недоступен» для нас **обычное состояние, а не авария**.

Клиент спрашивает GitHub, и **при любом его отказе** идёт на наш сайт. Пока GitHub отвечает,
сайт не запрашивается вовсе.

## 2. Контракт эндпоинта

### Запрос

```
GET https://silentgate.lol/api/app-version
User-Agent: SilentGate/<версия> (Windows|Android)
```

**Один путь на обе платформы.** Раньше их было два (`app-version` и `app-version-android`), и
андроидный так и не создали — из-за чего телефон **молча не находил обновлений вообще**. Не
повторять: платформу, если она нужна, определять по `User-Agent`, а не по пути.

Аутентификации нет. Cookie нет. Тела нет.

### Ответ — 200 и JSON

```json
{
  "version": "1.5.1",
  "url": "https://silentgate.lol/download/SilentGateSetup-1.5.1.exe",
  "notes": "Что нового в этой версии, коротко и по-человечески",
  "page": "https://silentgate.lol/download"
}
```

| Поле | Обяз. | Что это |
|---|---|---|
| `version` | **да** | Версия вида `1.5.1`. Приставка `v` допускается — клиент её срежет. Пустая строка = ответ считается непонятным. |
| `url` | нет | Прямая ссылка на файл **для платформы запрашивающего**. ⚠️ Только `https` — по `http` клиент ссылку отбросит и покажет страницу вместо неё. |
| `notes` | нет | Текст «что нового». Показывается пользователю целиком. |
| `page` | нет | Страница загрузок. Открывается, когда `url` нет. По умолчанию `https://silentgate.lol/download`. |

Лишние поля игнорируются — добавлять можно, ломать формат нельзя.

### Как клиент это трактует

- `version` **новее** установленной → пользователю показывается уведомление с кнопкой.
- `version` равна или старее → «у вас последняя версия».
- Не 200, не JSON, нет `version` → **«проверить не удалось»**, с причиной.

⚠️ **Три исхода, а не два.** «Не смогли проверить» — это отдельный ответ, а не «обновлений нет».
Раньше клиент их путал и говорил «у вас последняя версия» человеку без сети; так делать нельзя
и на сервере: **не отдавайте 200 с текущей версией, когда на самом деле не знаете ответа.**
Лучше честный 503.

### Коды ошибок

| Код | Когда | Что делает клиент |
|---|---|---|
| `200` | есть ответ | разбирает |
| `404` | эндпоинта нет | считает проверку неудавшейся |
| `429` | слишком часто | то же; см. §4 про частоту |
| `5xx` | у нас беда | то же |

Отдавать `204` или пустое тело **не надо**: клиент воспримет это как «сервер ответил непонятным
образом», и это будет правдой.

## 2b. Бета-канал — отдельный эндпоинт (1.13.0)

Пользователь сам включает в настройках галочку «Получать бета-версии»
(`AppSettings.betaChannel`, по умолчанию выключена). Только тогда клиент спрашивает ЭТОТ
эндпоинт вместо основного — обычный путь (§2) продолжает работать как раньше и беты
никогда не увидит.

```
GET https://silentgate.lol/api/app-version-beta
User-Agent: SilentGate/<версия> (Windows|Android)
```

Формат ответа — **тот же самый**, что у `app-version` (§2), плюс одно необязательное поле:

```json
{
  "version": "1.13.0-beta.1",
  "url": "https://silentgate.lol/download/beta/SilentGateSetup-1.13.0-beta.1.exe",
  "notes": "Бета-канал и откат версии",
  "beta": true
}
```

| Поле | Обяз. | Что это |
|---|---|---|
| `beta` | нет | Булево. Альтернатива — строковое поле `channel` со значением `"beta"`. Любое из двух → клиент показывает плашку «БЕТА» и строку «это пре-релиз, автообновление его не разошлёт». Отсутствие обоих полей = `isBeta: false` — старый ответ (если кто-то по ошибке настроит этот путь на тот же файл, что и `app-version`) не сломается, но и бета-плашку не покажет. |

⚠️ **`app-version-beta` ДОЛЖЕН отдавать НОВЕЙШИЙ релиз, ВКЛЮЧАЯ пре-релизы** — сюда как раз
годится содержимое `/opt/updates/beta/` (1.12.0 там уже лежит). У основного `app-version`
(§2) логика ОБРАТНАЯ: он обязан продолжать отдавать последний СТАБИЛЬНЫЙ релиз и никогда —
бету, даже случайно. Не заводите общий генератор для обоих файлов без явного параметра
канала — один неверный флаг на билд-сервере разослал бы бету всем.

### Приоритет клиента при включённой галочке

Клиент спрашивает не только этот эндпоинт: основной источник для бета-канала — СПИСОК
релизов GitHub (`GET /repos/<owner>/<repo>/releases`, БЕЗ `/latest`), он отдаёт релизы от
новых к старым по дате публикации, и первый элемент — это «новейшее, включая пре-релизы»
(поле `prerelease` у каждого элемента и даёт `isBeta`). `app-version-beta` спрашивается
**только если GitHub недоступен** — ровно та же логика, что у пары (1)/(2) в §1.

Тот же список релизов (без фильтра по бете) клиент использует и для кнопки «Прежние
версии» (откат) — на сервере для неё ничего заводить не нужно, она читает GitHub напрямую.

## 2c. Поля самообновления (1.14.0)

Оба эндпоинта (`app-version` и `app-version-beta`) могут отдавать четыре новых
**необязательных** поля. Клиент ставит обновление сам, только если есть ВСЕ четыре плюс `url`;
не хватает хоть одного — прежнее поведение (кнопка-ссылка), никакой ошибки.

```json
{
  "version": "1.14.1",
  "url": "https://silentgate.lol/download/SilentGateSetup-1.14.1.exe",
  "notes": "Что нового",
  "page": "https://silentgate.lol/download",
  "asset": "SilentGateSetup-1.14.1.exe",
  "size": 35012345,
  "manifest": "https://silentgate.lol/download/SilentGate-1.14.1.manifest.json",
  "sig": "https://silentgate.lol/download/SilentGate-1.14.1.manifest.sig"
}
```

| Поле | Обяз. | Что это |
|---|---|---|
| `asset` | нет | **Точное** имя файла из `url`, как оно записано в манифесте. По нему клиент ищет актив в манифесте — сравнение побайтное, не «содержит». Для Android — имя APK под телефон (`…-arm64-v8a.apk`), для Windows — установщика. |
| `size` | нет | Размер файла в байтах, целое > 0 (число или строка с числом). |
| `manifest` | нет | Ссылка на `SilentGate-<версия>.manifest.json` этого релиза. Только `https`. |
| `sig` | нет | Ссылка на `SilentGate-<версия>.manifest.sig` этого релиза. Только `https`. |

⚠️ **Манифест и подпись отдавать БАЙТ В БАЙТ такими, какими они лежат в релизе GitHub.**
Подпись стоит над байтами файла: переформатировать JSON, менять перевод строки, «красиво
печатать» нельзя — клиент отвергнет подпись и не поставит ничего.

⚠️ **`version` в ответе обязан совпадать с `version` внутри манифеста.** Клиент сверяет их и
считает расхождение попыткой отката (`versionMismatch`) — например, если JSON обновили, а
манифест остался от прошлого релиза. Порядок выкладки из §3b это исключает: сначала все файлы,
потом JSON.

Сайту **не нужен** ключ подписи и не нужно проверять подпись самому: манифест подписывается
у владельца при выпуске (§3a), сайт его только раздаёт. Подменённый манифест клиент
отвергнет сам — ключа, которым он проверяет, на сервере нет.

## 3. Платформы и файлы

Клиент собирается под три артефакта (плюс эмуляторная сборка); к каждому релизу с 1.14.0
добавляются два служебных файла — манифест и подпись:

| Платформа | Файл | Кому |
|---|---|---|
| Windows, установщик | `SilentGateSetup-<версия>.exe` | **основной вариант**, его и отдавать в `url` |
| Windows, портативная | `SilentGate-Portable-<версия>.zip` | тем, кто не может ставить: рабочий компьютер, флешка |
| Android, телефон | `SilentGate-<версия>-arm64-v8a.apk` | **это нужно людям** |
| Android, эмулятор | `TEST-ONLY-emulator-SilentGate-<версия>-x86_64.apk` | только для тестов; префикс нарочно выводит файл из шаблона `SilentGate-*`, чтобы на страницу загрузок он не попадал |
| Манифест релиза | `SilentGate-<версия>.manifest.json` | клиенту для самообновления (§3a); на страницу загрузок не выводить |
| Подпись манифеста | `SilentGate-<версия>.manifest.sig` | то же |

`<версия>` у манифеста и подписи — **тег релиза без `v`**, у бет полный: `v1.14.1-beta.1` →
`SilentGate-1.14.1-beta.1.manifest.json`. Клиент ищет их по точному имени, собранному из тега.

### Формат манифеста

```json
{"version":"1.14.1","channel":"stable","assets":[{"name":"SilentGateSetup-1.14.1.exe","size":35012345,"sha256":"<64 hex, нижний регистр>"},{"name":"SilentGate-1.14.1-arm64-v8a.apk","size":81230968,"sha256":"<64 hex>"}]}
```

| Поле | Что это |
|---|---|
| `version` | Версия релиза без `v`; обязана равняться тегу. |
| `channel` | `stable` или `beta`. Бета-манифест клиент принимает только при включённой галочке «Получать бета-версии». |
| `assets[]` | Все файлы, которые клиент может скачать из этого релиза: `name` (точное имя актива), `size` (байты), `sha256` (hex). |

Файл пишет `tool/sign_release.dart` — одной строкой, с фиксированным порядком ключей; руками
не править. `.manifest.sig` — одна строка base64: подпись Ed25519 над байтами `.manifest.json`.

⚠️ **В `url` для Windows отдавайте УСТАНОВЩИК, не портативный архив.** Портативная версия —
осознанный выбор человека, а не то, что стоит подсовывать по кнопке «Обновить»: у неё данные
лежат рядом с программой, и распаковка в другое место выглядит как потеря подписок.
Портативную показывайте на странице `/download/` рядом, с пояснением, чем отличается.

⚠️ **Портативную версию НЕЛЬЗЯ обновлять, перезаписывая всю папку.** Внутри неё есть
`sg-data\` — там подписки, настройки и журнал пользователя. Обновление = распаковать архив
поверх, `sg-data` не трогая. Это же написано в `portable.txt` внутри архива.

⚠️ **Никогда не отдавайте телефону `x86_64`.** Оба файла содержат `.apk`, и подмена приведёт к
установке сборки, которая на телефоне не запустится. Если платформа не определилась — не
отдавайте `url` совсем, отдайте `page`: пусть человек выберет сам.

⚠️ **Никогда не отдавайте Android ссылку на `.exe`.** Это уже случалось, когда путь был общим.

Файлы обязаны лежать на `https` и отдаваться с `Content-Length`. С 1.14.0 он ещё и
проверяется: не равен размеру из манифеста — клиент рвёт закачку до тела. Без заголовка клиент
не покажет прогресс в процентах и сверит размер только по факту принятого.

## 3a. Выпуск релиза: подпись и чек-лист (1.14.0)

Подпись ставится **на машине владельца**, приватный ключ — `signing/update_ed25519.key`
(в `.gitignore`, на сервер и в CI не кладётся). Подробнее о ключе — `docs/CODE_SIGNING.md`.

1. **Сборка.** Бамп версии (`app/pubspec.yaml`, `core/app_info.dart`), затем:
   - `build-exe.bat` → `ISCC installer\silentgate.iss` → `installer\Output\SilentGateSetup-<версия>.exe`;
     портативный архив — `app\build\windows\x64\runner\SilentGate-Portable-<версия>.zip`;
   - `build-apk.bat` → `app\build\app\outputs\flutter-apk\` — телефонный и TEST-ONLY APK.

   Проверить живьём в VM и эмуляторе — правило из `CLAUDE.md`, до подписи.
2. **Только для беты на Windows — переименовать установщик до подписи.** Inno называет файл по
   версии exe (`SilentGateSetup-1.14.1.exe`), а клиент ищет актив, вырезая из имени версию
   ТЕГА (`1.14.1-beta.1`): файл без неё не найдётся, и самообновление превратится в ссылку.
   Для тега `v1.14.1-beta.1` установщик должен называться `SilentGateSetup-1.14.1-beta.1.exe`.
   APK переименовывать не нужно — они находятся по хвосту `-arm64-v8a.apk`.
3. **Подпись:**
   ```
   cd app
   dart run tool/sign_release.dart <версия> <stable|beta> <файл> [<файл>…]
   ```
   - `<версия>` — тег без `v`, у беты полный (`1.14.1-beta.1`);
   - `<stable|beta>` — `beta` для пре-релиза, `stable` для обычного;
   - файлы — **все активы релиза**, которые клиент может скачать: установщик, телефонный APK и
     **TEST-ONLY x86_64 APK** (им обновляется эмулятор на стенде); портативный архив можно
     включить тоже. Актива нет в манифесте — клиент его не поставит, это защита, а не
     недосмотр.

   Инструмент кладёт `SilentGate-<версия>.manifest.json` и `.manifest.sig` **рядом с первым
   файлом**. Имя актива в манифесте = имя файла на диске, поэтому все переименования — ДО
   подписи.
4. **Один релиз на GitHub со всеми активами сразу**: сами файлы + `.manifest.json` +
   `.manifest.sig`. После подписи файлы не пересобирать, не переименовывать и не
   перезаливать по одному: другой хэш или имя — клиент откажет (`assetMissing` или
   несовпадение sha256) и покажет ссылку/ошибку вместо обновления.
5. Если по правилу «стабильный выше, бета ниже» Windows и Android выходят РАЗНЫМИ релизами
   (`v1.14.1` и `v1.14.1-beta.1`) — у каждого свой манифест, подписанный со своей версией и
   своим каналом. Манифест одного релиза в другой не класть.

Проверка результата — `curl` по активам релиза (§7); сверить, что имена в манифесте
совпадают с именами активов на странице релиза.

## 3b. Откуда сайт берёт файлы: САМ, С GITHUB

⚠️ **Это главное изменение в процедуре, и оно снимает с владельца ручную работу.**

Раскладка ролей такая:

| Кто | Что делает |
|---|---|
| Клиентская команда | публикует релиз **только на GitHub** (файлы + тег) |
| **Сайт** | сам замечает новый релиз, забирает файлы к себе и обновляет свои JSON |
| Клиент у пользователя | спрашивает GitHub, а при отказе — сайт |

**Почему так, а не «владелец загружает файлы руками».** GitHub у пользователей в России
недоступен (см. §1 — API перехватывают на TLS), а **у сервера — доступен**: он стоит там, где
не блокируют. Значит сервер может быть мостом: он видит GitHub, пользователь видит сервер.
Ручная выкладка при этом лишняя и опасна — именно на ней 15.08.2026 на сайт попал APK от 13.08,
а эндпоинт при этом объявлял `1.5.1`: человек скачал бы старую сборку, поверив версии.

### Что должен делать сайт

Периодически (раз в 10–15 минут достаточно) спрашивать:

```
GET https://api.github.com/repos/<owner>/<repo>/releases/latest
Accept: application/vnd.github+json
```

Из ответа брать `tag_name` (версия, приставку `v` срезать) и `assets[].browser_download_url`.

Дальше, **и порядок здесь важен**:

1. Сравнить `tag_name` с тем, что уже отдаётся. Совпало — ничего не делать.
2. Скачать артефакты во **временный** каталог, не в боевой.
3. ⚠️ **Проверить целостность.** У GitHub есть `assets[].size` — сверить с фактическим
   размером скачанного. Половина файла, приехавшая при обрыве, выглядит как файл.
4. Переложить в `/opt/updates/` **атомарно** (скачали рядом → `mv`), чтобы никто не успел
   скачать половину.
5. ⚠️ **И ТОЛЬКО ПОТОМ** обновить `version`/`url` в JSON. Обратный порядок даёт окно, в
   котором эндпоинт обещает версию, файла которой ещё нет, — то есть 404 по кнопке «Скачать».
6. `notes` брать из `body` релиза. Обрезать до разумной длины: это всплывающая карточка.
7. **1.14.0:** вместе с артефактами забирать `SilentGate-<версия>.manifest.json` и
   `.manifest.sig` (без изменений, байт в байт) и заполнять поля §2c: `asset` — имя файла из
   `url`, `size` — его `assets[].size`, `manifest`/`sig` — ссылки на свои копии. Нет
   манифеста в релизе (всё до 1.14.0) — полей §2c не отдавать вовсе.

### Чего сайт делать НЕ должен

- **Не публиковать черновики и предрелизы.** `/releases/latest` их и так исключает — не
  переходите на `/releases` без фильтра `draft == false && prerelease == false`.
- **Не удалять прежние файлы сразу.** Держите хотя бы предыдущую версию: если новая окажется
  сломанной, откат — это правка одной строки в JSON, а не срочная пересборка.
- **Не понижать версию молча.** Если `tag_name` оказался СТАРШЕ уже опубликованного (тег
  переписали, релиз удалили) — не откатываться автоматически, а оставить как есть и сообщить
  владельцу. Автоматический откат versions — это способ разослать всем старую сборку одним
  неверным движением на GitHub.
- **Не ходить на GitHub чаще раза в 10 минут.** Неавторизованный лимит — 60 запросов в час на
  адрес, и его делят все процессы сервера.

### Пока репозиторий закрыт

Сейчас `github.com/<owner>/<repo>` **приватный**, и `/releases/latest` отдаёт `404`. Это
ожидаемо и не поломка: пока так, сайт продолжает отдавать то, что в JSON лежит сейчас, а
файлы кладутся вручную (§9). Как только репозиторий откроют — синхронизация заработает
сама, без правок на сервере.

⚠️ Если понадобится читать приватный репозиторий до его открытия — это токен GitHub на
сервере. Тогда: токен только на чтение (`Contents: read`), в переменной окружения, **никогда**
в ответе эндпоинта и не в логах.

## 4. Нагрузка, кэш, частота

- Клиент спрашивает **один раз при запуске** (если проверка включена в настройках) и по нажатию
  кнопки в настройках.
- Ответ маленький и одинаковый для всех — **кэшируйте**. `Cache-Control: public, max-age=300`
  разумно: пять минут задержки в доставке новости о версии никому не мешают, а всплеск после
  релиза сглаживают.
- Ограничение частоты по адресу допустимо, но **не жёстче 60 запросов в час** — за одним адресом
  сидит и квартира, и офис. При отказе отдавайте `429`, а не `403`: клиент различает их в
  сообщении человеку.

## 5. Чего делать НЕЛЬЗЯ

Это раздел про безопасность и доверие, и он важнее остальных.

1. **Не требовать подписку.** Обновление приложения одинаково для всех — и для тех, у кого
   подписка кончилась. Привязка версии к оплате превратит клиент в заложника биллинга.
2. **Не отдавать разным людям разные версии.** У сервера есть такая возможность (он знает
   пользователя), и именно поэтому он **запасной**, а не основной: чтобы подменить версию,
   пришлось бы подменить оба источника сразу.
3. **Не логировать пользователей.** Запрос анонимный. Не сохраняйте `User-Agent` вместе с
   адресом в долгую таблицу: связка «адрес + версия клиента + время» — это профиль.
   Достаточно счётчиков без персональных данных.
4. **Не отдавать `http`-ссылку на установщик.** Клиент её отбросит, но проблема в самом
   намерении: установщик по открытому каналу можно подменить.
5. **Не ставить редирект на сторонний хостинг файлов** без крайней нужды. Если делаете —
   редирект обязан быть на `https`.

## 6. Сообщения пользователям — отдельная история

Владелец просил описать и это. **Не смешивайте с обновлениями**: `notes` — это «что нового в
версии», а не канал объявлений.

### Что уже есть в клиенте

Панель Remnawave умеет присылать в ответе подписки поля `title` и `announce` — они показываются в
карточке подписки. Это **работающий канал объявлений**, и для «у нас профилактика в субботу» он
подходит лучше нового эндпоинта. Прежде чем строить своё, проверьте, хватает ли его.

### Если всё-таки нужен свой канал

Отдельный эндпоинт, отдельный формат:

```
GET https://silentgate.lol/api/notice
```

```json
{
  "id": "2026-08-maintenance",
  "level": "info",
  "text": "В субботу с 3:00 до 5:00 по МСК возможны перебои.",
  "url": "https://silentgate.lol/blog/maintenance",
  "until": "2026-08-20T02:00:00Z"
}
```

| Поле | Зачем |
|---|---|
| `id` | ⚠️ **Обязательно.** По нему клиент запоминает, что сообщение уже показывал. Без `id` объявление всплывало бы при каждом запуске — так делают приложения, которые перестают читать. |
| `level` | `info` / `warning` / `critical`. Влияет на вид, а не на назойливость. |
| `text` | Текст. Коротко: это всплывающая карточка, а не письмо. |
| `url` | Необязательная ссылка «подробнее». |
| `until` | Когда сообщение протухает. После этой даты клиент его не показывает, даже если сервер продолжает отдавать. |

Пустой ответ (`{}` или 204) означает «объявлений нет» — это нормальный, ожидаемый ответ.

⚠️ **Одно сообщение за раз.** Очередь объявлений на экране — это шум, от которого отмахиваются,
не читая. Если новостей несколько, решайте на сервере, какая важнее.

⚠️ **`critical` — не для маркетинга.** Как только этим уровнем придёт реклама, люди перестанут
читать и настоящие предупреждения. Уровень оправдан для «сервис недоступен» и «смените версию,
в старой дыра».

### Обратная связь ОТ пользователей

Сейчас её нет и по умолчанию **не надо**. Клиент собирает отчёт для поддержки и открывает чат
Telegram — человек отправляет сам, осознанно, видя содержимое файла. Это правильно: в отчёте
техническая информация о его машине.

Если когда-нибудь захотите приём отчётов на сервер — это отдельное решение с явным согласием,
и вот минимальные требования, без которых начинать не стоит:

1. **Только по кнопке пользователя.** Никакой фоновой отправки.
2. **Показать, что именно уходит**, до отправки. Отчёт содержит версии, настройки, журнал.
3. **Срок хранения и удаление по запросу.** Отчёты — это данные человека.
4. **Не принимать то, чего не просили:** ограничение размера, никакого исполняемого содержимого.
5. ⚠️ **Проверить, что в отчёте нет секретов.** Клиент уже маскирует токен подписки, адреса
   серверов и пароли — но это делает *клиент*. Сервер обязан считать входящее недоверенным.

## 7. Как проверить, что сделано верно

```bash
# 1. Отвечает и разбирается
curl -s https://silentgate.lol/api/app-version | jq .

# 2. Версия есть и выглядит версией
curl -s https://silentgate.lol/api/app-version | jq -r .version

# 3. Ссылка на https и файл реально существует
curl -sI "$(curl -s https://silentgate.lol/api/app-version | jq -r .url)" | head -1

# 4. Android получает apk, а не exe
curl -s -A 'SilentGate/1.5.1 (Android)' https://silentgate.lol/api/app-version | jq -r .url
# ожидаем …-arm64-v8a.apk

# 5. Windows получает exe
curl -s -A 'SilentGate/1.5.1 (Windows)' https://silentgate.lol/api/app-version | jq -r .url
# ожидаем …Setup….exe
```

Готово, когда все пять дают ожидаемое, а `curl` без `User-Agent` не роняет сервер.

С 1.14.0 (§2c) — ещё три:

```bash
# 6. Поля самообновления на месте, адреса на https
curl -s -A 'SilentGate/1.14.0 (Windows)' https://silentgate.lol/api/app-version | jq '{asset,size,manifest,sig}'

# 7. Манифест той же версии и содержит asset с тем же размером
J=$(curl -s -A 'SilentGate/1.14.0 (Windows)' https://silentgate.lol/api/app-version)
curl -s "$(echo "$J" | jq -r .manifest)" | jq --arg a "$(echo "$J" | jq -r .asset)" '.version, (.assets[] | select(.name==$a) | .size)'
# ожидаем: .version из ответа эндпоинта и .size из него же

# 8. Манифест отдаётся байт в байт как в релизе GitHub
cmp <(curl -sL https://github.com/<owner>/<repo>/releases/download/v<версия>/SilentGate-<версия>.manifest.json) \
    <(curl -s "$(echo "$J" | jq -r .manifest)") && echo OK
```

## 9. Реализация на сервере — СДЕЛАНО 15.08.2026

Эндпоинт живёт **в Caddy, не во Flask** — сознательно: запасной канал обновлений обязан
отвечать, даже когда сайт-приложение лежит (в этом весь его смысл), и он не тянет за собой
цикл релизов сайта. Проверен весь чек-лист §7 с внешней сети.

**Как устроено** (мейн-нода, vhost `silentgate.lol` в `/opt/remnawave/caddy/Caddyfile`):
- `GET /api/app-version` — Caddy по `User-Agent` выбирает один из трёх статических файлов
  в `/opt/updates/`: `version-android.json` / `version-windows.json` /
  `version-generic.json` (без UA или неизвестная платформа → generic, `url` отсутствует —
  ровно как требует §3). Заголовок `Cache-Control: public, max-age=300` (§4).
- `GET /api/notice` — `/opt/updates/notice.json`, сейчас `{}` («объявлений нет»).
- `GET /download/<файл>` — `file_server` из `/opt/updates/` (https, `Content-Length` есть);
  `/download/` — автолистинг, «пусть человек выберет сам».
- **Приватность (§5.3) — ОТМЕНЕНО ВЛАДЕЛЬЦЕМ 17.08.2026.** Изначально на всех этих путях
  стоял `log_skip` (в access-лог не попадало ничего, проверено: 0 записей). Владелец решил
  строить аналитику обращений и загрузок, и `log_skip` снят со всех пяти путей
  (`/api/app-version` ×3 матчера, `/api/notice`, `/download*`). Теперь в лог пишутся
  IP, UA, путь с query, статус, отданные байты и `Range`.
  Что сделано взамен, чтобы отступление не превратилось в утечку:
  * `Cookie`, `Authorization` и `Set-Cookie` вырезаются самим Caddy
    (`format filter` → `fields { … delete }`) — проверено на живых записях;
  * сырой лог короткий: `roll_size 50mb`, `roll_keep 3`;
  * IP в аналитической БД хранится не открытым текстом, а как HMAC (для агрегатов)
    + AES-GCM (для раскрытия), раскрытие — только через хаб с 2FA и отдельным правом,
    факт раскрытия пишется в аудит.
  До Flask эти пути по-прежнему не доходят — журналирование IP на стороне сайта их не видит.
  ⚠️ Грабли на будущее: **`caddy reload` НЕ переоткрывает лог-файлы.** Если файл лога
  подменить (`mv`, `sed -i`, `os.replace`), Caddy молча продолжит писать в удалённый inode,
  и лог «замрёт» без единой ошибки. Лечится только рестартом контейнера; хвост из
  осиротевшего дескриптора вычитывается через `/proc/<pid>/fd/<n>`.
- Rate-limit не ставился (§4 соблюдён автоматически), 200-с-неправдой невозможен: нет
  файла/каталога → честный не-200.
- Каталог смонтирован в контейнер Caddy read-only (`/opt/updates:/opt/updates:ro`
  в `docker-compose.yml`).

**Как выпустить новую версию** (процедура для владельца):
1. Положить артефакты в `/opt/updates/` на мейн-ноде с версией в имени:
   `SilentGate-<версия>-arm64-v8a.apk`, `SilentGateSetup-<версия>.exe`.
2. Обновить `version`, `url`, `notes` в `version-android.json` и `version-windows.json`
   (и `version` в `version-generic.json`). Ничего перезапускать не нужно.
3. ⚠️ **И `.published_version` тоже** — это не служебный файл, а состояние синхронизатора:
   `published_version()` в `sync_github.py` читает **его первым**, а JSON только запасным
   вариантом. Оставите там прежнюю версию — и в день, когда репозиторий откроют, автосинк
   сравнит тег GitHub со СТАРЫМ числом и спокойно опубликует релиз, который старше того, что
   уже отдаётся: защита «не понижать версию» (§3b) сработает не на ту величину.
4. Обновить `index.html` — это и есть страница `/download`, на которую клиент уходит, когда
   `url` нет. Её ссылки живут отдельно от JSON и рассинхронизируются молча.

Выложены все четыре артефакта: `SilentGate-1.6.2-arm64-v8a.apk` (81 230 968 Б),
`SilentGate-1.6.2-x86_64.apk`, `SilentGateSetup-1.6.2.exe` (34 932 418 Б),
