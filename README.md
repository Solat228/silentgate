# SilentGate

Кроссплатформенный VPN-клиент для экосистемы **SilentGate** (панель Remnawave + Telegram-бот + сайт).
Один UI-код на **Flutter/Dart**, движок — **Xray-core** (VLESS/Reality) плюс **sing-box**
отдельным процессом для TUN и **Hysteria2**. Авторизация — через Telegram-бота.

> Статус: **v1.6.5 (бета)**. Первый таргет — **Windows**, идёт порт на **Android**. Все режимы
> прогнаны живым тестом в изолированной VM на реальных подписках.
>
> **Что изменилось в 1.6.1:** правило приложения «по пути» переставало действовать после
> обновления самой программы — у тех, чей путь содержит версию, обновление меняет путь, и правило
> тихо перестаёт совпадать. При этом в списке оно выглядело полностью здоровым. Воспроизведено
> опытом в VM: трафик, помеченный «Прямо», уходил в туннель, а в логе ядра не оставалось ни одной
> строки совпадения. Теперь мёртвый путь помечен, и одно нажатие переводит правило на
> сопоставление по имени файла.
>
> **Что изменилось в 1.6.0:** автонастройка перестроена — сначала быстрый TCP-отсев по всем
> серверам, дорогая проверка только по выжившим, перебор вариаций только для тех, кто не ответил
> внятно; несколько серверов проверяются одновременно. Появилась гео-проверка: сервер, на котором
> ChatGPT отвечает «недоступно в вашей стране», больше не выдаётся за полностью рабочий. Сервисы,
> проверяемые при подключении, теперь выбираются в подменю на главном экране, а данные подбора
> видны в «О сервере». Плюс три отдельных переключателя бесшовности и предупреждение о расходе
> трафика перед замером скорости.
>
> **Что изменилось в 1.5.2:** установщик. Обновление поверх **запущенного** приложения молча не
> срабатывало — а с треем оно запущено почти всегда, то есть отказ приходился на самый частый
> случай обновления. Старый установщик, запущенный поверх новой версии, так же молча откатывал
> программу назад. Оба случая найдены прогоном полной матрицы в VM и закрыты; мастер теперь прямо
> говорит, что идёт обновление и что настройки сохранятся, показывает лицензию, знает 8 языков и
> ведёт на сайт из «Программ и компонентов». Разбор «менять ли формат установщика на MSI/MSIX» —
> `docs/research/INSTALLER_CHOICE.md`.
>
> **Что изменилось в 1.5.1:** разбор двух поломок, которые принесла 1.5.0. Скачивание гео-баз
> тянуло файлы ИЗ ДРУГОГО ПРОЕКТА и подменяло ими рабочие: список доменов худел впятеро, и весь
> российский трафик, который панель отправляет напрямую, уезжал через VPN — при этом ядро молчало.
> Теперь источник тот же, что в поставке, есть резервная копия с возвратом одной кнопкой, а замена
> не ставится, если в новом файле нет категорий вашей подписки. На Android приложение зависало:
> подъём обоих ядер шёл на главном потоке, а запуск ждал нативную сторону без срока — теперь работа
> ушла в фон, а в журнале появилась отметка живости (раньше отличить «зависло» от «нечего писать»
> было нечем). Плюс вернулись иконки у правил «по имени», сервис-чипы перестали перепроверяться при
> смене сервера, и плашка с именем сервера больше не наезжает на кнопку.
>
> **Что изменилось в 1.5.0:** на Android VPN не поднимался вовсе — приложение падало в цикл раз
> в секунду с заблокированным трафиком; причина найдена, воспроизведена на эмуляторе и закрыта.
> Ядро на телефоне теперь видит гео-базы (передаём каталог внутри конфига: переменную окружения,
> выставленную из Java, рантайм Go не видит в принципе). Появились скачивание гео-баз по кнопке,
> замер скорости на телефоне и проверка обновлений через релизы GitHub — с честным «проверить не
> удалось» вместо молчаливого «у вас последняя версия». Профили «Авто» стали пинговаться верно:
> проба шла на балансировщик и мерила прямой канал вместо сервера.
>
> **Что изменилось в 1.4.3:** порт проверки серверов на Android слушал **без пароля** — на время
> пинга любое приложение телефона получало вход в туннель проверяемого сервера; закрыто.
> Профиль «Авто» мог молча исчезнуть после обновления с прошлой версии: ключ профиля строился
> только из названия, а у четырёх подписок названия совпадают. Адреса ваших серверов больше не
> попадают в отчёт для поддержки — ни из журнала приложения, ни из логов ядер, где их было
> больше всего. Счётчики подписок перестали выдавать недосчитанное за окончательный результат.
>
> **Что изменилось в 1.4.2:** ключ сервера перестал зависеть от написания ссылки —
> раньше при смене формата ответа панели терялись пины, ручные правки и результаты
> пинга (у владельца осиротело 273 записи из 374). Данные переносятся сами при первом
> запуске. Попутно закрыта утечка: токен подписки попадал в журнал, а тот целиком
> вкладывается в отчёт для поддержки. Скорость сервера теперь видна прямо в списке —
> и меряется только у тех, кто прошёл проверку канала. Настройки получили поиск,
> ограничение ширины, сворачиваемые разделы и меню слева; API уехал на свой экран.
>
> **Что изменилось в 1.4.0:** локальный HTTP-API для автоматизации (`docs/API.md`,
> `tools/silentgate.py`) — статус, список серверов, переключение и отключение из скрипта, плюс
> отдельный порт на каждый сервер (`10820…10859`), чтобы направить конкретный запрос через
> конкретную страну, не трогая маршрут остальной машины. Новый режим захвата «Только прокси»:
> ядро поднимается и порты слушают, а сама машина остаётся полностью мимо VPN. Выключено по
> умолчанию, требует токена — пустой токен означает, что канал не поднимается вовсе. Заодно
> закрыт порт `47654`: управляющие команды через локальный сокет теперь тоже требуют токен.
>
> **Что изменилось в 1.3.0:** обрыв связи больше не проходит молча. «Подключено» раньше означало
> «туннель поднялся», а не «трафик ходит»: ядро могло перестать отвечать, и приложение об этом не
> знало. Появился сторож канала — сквозной запрос через живое ядро, три промаха подряд считаются
> смертью канала и вызывают переподъём (проверено живьём: обрыв в 20:36:39, туннель поднят заново
> в 20:36:45). На Windows сообщения об этом идут системным уведомлением: окно почти всегда
> свёрнуто в трей, и карточка внутри приложения уходила в никуда. Локальные порты ядра закрыты
> паролем по умолчанию — без него туннель целиком доступен любой программе на той же машине.
> Таймер соединения теперь считает от нажатия кнопки и не сбрасывается переподключением.
> Страница-заглушка при блокировке заменена уведомлением: подменить https без своего корневого
> CA невозможно, а ставить CA нельзя.
>
> **Что изменилось в 1.2.0:** несколько выходов одновременно — у каждого правила раздельного
> туннелирования свой. Проверено живьём на обеих платформах и совпало до последнего адреса:
> `2ip.ru` через Германию, `ipinfo.io` через США, `dnsleak.com` напрямую.
>
> **Что изменилось в 1.1.0:** разбор жалобы «добавил сайт — интернет пропал». Правило по сайту
> включало запрет QUIC и IPv6 **на всю машину**, хотя тумблер был выключен; DNS отмеченных
> приложений уходил мимо туннеля из-за полного пути в поле, где ядро ждёт имя файла; перезапуск
> туннеля по правке настроек не оставлял в журнале причины. Восемь режимов раздельного
> туннелирования перепроверены живьём: прямо, туннель, блок и заглушка отвечают как обещано.
> Отдельно: на Android kill switch и автопереподключение молча выключались после сворачивания
> приложения — обе галочки оставались включёнными, а защиты за ними не было; и ответ одной
> подписки мог затереть другую, если переключиться, пока идёт загрузка. APK для телефона
> похудел со 135 до 76 МБ. Подключение проверено живым прогоном на эмуляторе.
> Плюс исследование `docs/research/VPN_DETECTION.md`: факт включённого VPN на Android скрыть
> нельзя — но можно не пускать приложение в туннель, и это уже работает.
>
> **Что изменилось в 1.0.2:** устранены два разных зависания подключения на Windows (запрос прав
> администратора и проверка сетевых адаптеров — оба могли не возвращаться вовсе); мешающий чужой
> VPN теперь определяется по имени программы и закрывается кнопкой прямо перед подключением;
> заблокированный сайт открывает страницу-заглушку с объяснением вместо ошибки соединения (только
> http — подмена https без своего корневого сертификата невозможна); автоподбор лучшего сервера
> умеет учитывать скорость, взвешенно к вашему собственному каналу.
>
> **Безопасность и маршрутизация (v0.12.0):** устранена **утечка реального IP** на «Авто»/панельных
> профилях — их внутренний `direct` (RU-routing) переписывается через VPN в режиме «Всё через VPN» и
> при новой галочке «Не выходить под реальным IP» рядом с kill switch; блок сайта теперь важнее
> «Туннель»-приложения (порядок правил); трафик панельных профилей снова считается (агрегация всех
> прокси-outbound + StatsService).
>
> **Проверка сервисов и автонастройка (v0.13.0):** у кнопки Connect — чипы **YouTube/ChatGPT/Telegram**
> с живой проверкой по активному соединению (только ручной тап; для ИИ — детект гео-блокировки страны
> выхода; цвет + задержка). Автонастройка расширена (+Claude/Gemini/X/Instagram/Google, бренд-иконки,
> «выбрать/снять все», дефолт YouTube/ChatGPT/Telegram). Плюс интервал автообновления с приоритетом,
> видимая «!»-легенда у пинга, пометка панельных серверов со сводкой их маршрутизации, тост о переборе
> стека/MTU TUN, фавиконки сайтов с одним `.ico`.
>
> **База:** мультиязычность (`flutter_localizations`/ARB, **10 языков** ru/en/es/fr/de/pt/tr/ar/fa/zh,
> вкл. RTL; спека — [docs/I18N.md](docs/I18N.md)); опциональная подпись кода
> ([docs/CODE_SIGNING.md](docs/CODE_SIGNING.md)); **раздельное туннелирование** по модели v2raytun
> (у приложения: Туннель/Прямо/Блок; у сайтов — порт и дерево поддоменов); **TUN** на sing-box без UAC
> (задача Планировщика) с автоподбором стека/MTU; **Hysteria2** вторым прокси-ядром (обфускация,
> порт-хоппинг, автовыбор `urltest`); **автовыбор лучшего сервера** (Xray balancer + burstObservatory),
> в т.ч. панельные XRAY_JSON-профили целиком; несколько подписок с переключением; пинг TCP→GET/HEAD;
> экран информации о сервере (IP/гео/скорость); проверка обновлений приложения; трей, темы, kill switch,
> автопереподключение, восстановление сети; отчёт для поддержки без секретов; установщик Inno Setup.
> Полная история версий — в [CHANGELOG.md](CHANGELOG.md). Дальше: живое тестирование, затем macOS/Linux
> и мобильные.
>
> Журнал изменений — [CHANGELOG.md](CHANGELOG.md). Инструкции для Claude Code — [CLAUDE.md](CLAUDE.md).
> Как это работает (язык, сборка, TUN) — [docs/HOW_IT_WORKS.md](docs/HOW_IT_WORKS.md).

## Зачем свой клиент

Сейчас пользователи подключаются через сторонние клиенты (Happ, v2RayTun, Streisand) по deep-link'ам,
которые уже генерирует сайт (`happ://add/…`, `v2raytun://import/…`). Свой клиент даёт:

- **Контроль над UX и брендом** (у сторонних клиентов — своя реклама, свои «рекомендованные VPN»).
- **Бесшовную авторизацию через Telegram** без ручного копирования ссылок подписки.
- **Единую точку** для будущей коммерции (личный кабинет, продление, оплата) прямо в приложении.
- **Защиту от увода подписок** (зашифрованные ссылки по образцу Happ crypto-links).

Подробное обоснование и результаты исследования Happ / v2RayTun / v2rayNG / NekoBox / Hiddify — в
[docs/STACK_DECISION.md](docs/STACK_DECISION.md) и [docs/research/RESEARCH_SUMMARY.md](docs/research/RESEARCH_SUMMARY.md).

## Стек (кратко)

| Слой | Технология | Почему |
|---|---|---|
| UI (все платформы) | **Flutter / Dart** | Один код на Windows/Android/iOS/macOS/Linux. Путь v2RayTun (Win) и Hiddify (всё). |
| Движок | **Xray-core** (Go) | Референс VLESS/XTLS-Vision/Reality, доминирует в RU-экосистеме. Лицензия **MPL-2.0** — совместима с GPL-3.0, поставляется отдельным бинарником. |
| Привязка ядра — Desktop | `xray.exe` **отдельным процессом** | UI просто запускает и управляет процессом. Обновление ядра = замена бинарника. |
| Привязка ядра — Android | самосборный **gomobile AAR** из `libXray` (MIT) | in-process в `VpnService`. |
| Привязка ядра — iOS | **libXray.xcframework** в нативном Swift `NEPacketTunnelProvider` | Dart не может работать в extension. |
| Захват трафика — Windows MVP | системный прокси (реестр WinINET) | Без TUN-драйвера и прав администратора. TUN — позже. |
| Бэкенд/авторизация/оплата | **Python** (существующие боты) + Remnawave API | Ваш основной язык; логика остаётся на сервере. |

Полностью: [docs/STACK_DECISION.md](docs/STACK_DECISION.md).

│   │   ├── state/                 ← AppState, SettingsController, ProbeController, AutoConfigController, ServiceCheckController

в `lib/engine/<platform>/` (Dart через conditional imports) и в нативных папках `app/<platform>/`
(Kotlin для Android, Swift для iOS). Планы и список фич каждой версии — в `docs/platforms/<PLATFORM>.md`.

## Быстрый старт (Windows, для разработки)

> Требуется один раз установить Flutter SDK и загрузить ядро Xray.

```powershell
# 1. Установить Flutter SDK (если ещё нет) — см. tools/bootstrap-windows.ps1
#    Клонирует flutter/flutter в C:\Users\<you>\flutter и добавляет в PATH.

# 2. Загрузить ядро xray.exe в engine/windows/bin/
powershell -ExecutionPolicy Bypass -File tools/fetch-xray.ps1

# 3. Запустить приложение на Windows
cd app
flutter pub get
flutter run -d windows
```

Подробности разработки Windows-версии — в [docs/platforms/WINDOWS.md](docs/platforms/WINDOWS.md).

## Лицензия

Клиентское приложение SilentGate распространяется под **[GNU GPL-3.0](LICENSE)**. Форки и
производные обязаны оставаться открытыми под той же лицензией. Бэкенд и панель `silentgate.lol` —
отдельный коммерческий сервис (в этот репозиторий не входят).

### Лицензии зависимостей

- **Xray-core — MPL-2.0**: совместим с GPL-3.0 (копилефт на уровне файлов); поставляется **отдельным
  бинарником**, не линкуется.
- **sing-box — GPL-3.0**: поставляется **отдельным процессом/бинарником**; исходники — у апстрима
  (`SagerNet/sing-box`).
